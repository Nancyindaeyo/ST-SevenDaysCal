## 失败项

### F-01 — 阻断级：旧版迁移在确认持久化之前删除唯一数据源

证据：

- `store.js:100-119`：`persist()` 调用 `saveMetadata()`/外部持久化，但不等待或验证结果。
- `store.js:739-756`：`migrateChatFromLocalStorage()` 修改 `sp-store`，调用 `persist()`，立即删除每个旧版键，并返回 `status: 'migrated'`。
- `store.js:771-779`：当用户选择本地副本时，`applyLegacyOverCloud()` 采用相同的执行顺序。
- 没有测试导入或执行 `migrateChatFromLocalStorage()` 或 `applyLegacyOverCloud()`。

失败过程：

1. 唯一的持久副本位于 `localStorage`。
2. 代码将值写入实时 `chat_metadata`。
3. `saveMetadata()` 返回一个随后被拒绝的 Promise，或宿主保存操作在聊天切换期间被取消。
4. 迁移已经删除 `localStorage` 副本并报告成功。
5. 重新加载后，迁移的数据丢失。

这与仓库在 `writeDataConfirmed()` 和 `writeBatchConfirmed()` 中其他方面谨慎的确认写入设计相矛盾。

必需修复：

- 将破坏性迁移改为异步。
- 通过绑定目标且带确认机制的写入器进行持久化。
- 仅在提交得到确认后删除旧版键。
- 遇到 `commitState: 'unknown'` 时，保留数据源并停止；不要自动重试覆盖写入。

必需证明：

- 针对确认成功、Promise 被拒绝、未派发失败、未知提交、保存期间切换聊天和 localStorage 删除失败的测试。

### F-02 — 高危：聊天切换期间，上一聊天的潜在提示词在加载过程中仍处于启用状态

证据：

- `runtime/chat-changed.js:3-58` 启动边界并中止工作，但在等待外部加载之前不会清除线、纲要或台账提示词。
- `runtime/chat-changed.js:58-77` 仅在 `loadExternalChat()`、迁移和 ID 迁移完成后刷新这些提示词。
- `runtime/plugin-lifecycle.js:72-81` 已有必需的清除端口，但仅在禁用插件时使用。
- `runtime/chat-changed.test.js:80-121` 验证了加载后刷新，但没有断言旧提示词会在 `loadExternalChat()` 之前被清除。
- `docs/运行逻辑与规则.md:272` 和 `docs/路线图.md:45-66` 明确承认了这一缺口。

影响：

如果启用了潜在注入，并且用户在切换聊天后立即发送消息，则新的生成可能收到上一聊天中的线/纲要/台账内容。写入守卫可防止旧任务提交到新聊天，却无法保护生成输入。

必需修复：

- 在边界开始时同步清除每个聊天作用域提示词。
- 仅当新聊天加载完成且仍为当前聊天时，才重新启用提示词。
- 明确分类不属于聊天作用域的契约，例如时间戳契约。

必需证明：

- 一项延迟加载测试，断言等待前清除、当前聊天加载后刷新。
- 一项快速 A → B → C 测试，证明 B 无法将提示词恢复到 C 中。

### F-03 — 高危：活动持久化报告成功，但实际静默退化为仅内存状态

证据：

- `business/activity/store.js:59-72` 在持久化存储不可用或两次写入均抛出异常后返回 `{ ok: true, memoryOnly: true }`。
- `business/activity/store.js:11-39` 迁移旧版活动条目，并在未检查 `write()` 是否成功的情况下删除旧版键。
- `index.js:1336-1344` 的生产接线传入 `writeStore(...)`，其布尔结果被迁移适配器忽略。
- `business/activity/activity.test.js:291-310` 的现有覆盖只测试成功的内存模拟写入；不存在失败测试。

影响：

“最近更改”的审计/重试历史可能在重新加载后消失，而调用方却被告知写入成功。在旧版迁移期间，目标写入失败后，原有持久副本也可能被删除。

这是静默的内存回退，而不是确认式持久化策略。

必需修复：

- 传播持久写入失败。
- 除非每个调用方都将仅内存状态显式标记为易失，否则不要为该状态返回 `ok: true`。
- 在目标持久化成功之前，不要删除旧版数据源。

必需证明：

- 针对 `write() === false`、写入抛出异常、存储不可用、失败后重新加载以及旧版数据得到保留的测试。

### F-04 — 中危：生命周期关键失败被吞掉

### F-09 — 高危：楼层队列在排空期间静默拒绝入队任务

证据：

- 当 `busy` 为 true 时，`business/refresh/floor-queue.js:87-100` 立即返回 `false`；它不会追加到积压队列，也不会记录被跳过/失败的任务。
- `index.js:1465-1470` 返回该布尔值，但不记录日志、活动、重试计划或用户可见状态。
- `business/refresh/floor-queue.test.js` 覆盖顺序和失败，但未覆盖排空期间入队。

影响：

如果一个缓慢的楼层任务正在运行，而另一条生产路径为同一当前楼层将一个到期任务入队，则第二个任务会消失。它既不在已排队、已跳过、已失败状态中，也不在活动状态中，这与文档记载的“同楼层任务串行运行”契约相矛盾。

确切发生频率取决于 SillyTavern 的异步事件调度，因此仍需运行时复现。静默拒绝本身已由控制流证实。

必需修复：

- 排空期间，将相同身份的任务接收到待处理积压队列中，并执行 ID 去重和固定排序；或者返回调用方必须记录并重试的类型化拒绝。
- 明确拒绝不同楼层身份，而不是将其与普通忙碌状态混为一谈。

必需证明：

- 保持第一个任务的 Promise 未完成，在忙碌时将第二个任务入队，再释放第一个任务，并证明第二个任务要么运行，要么以明确的可重试失败形式出现。

### F-10 — 高危：刷新/战斗重试元数据在活动规范化期间被丢弃

证据：

- `business/refresh/controller.js:256-264` 创建包含 `kind`、原始 `reason`、`feedback` 和 `outlineMode` 的刷新活动条目。

影响：

- 对旧活动条目进行版本化处理或提供安全默认值。

必需证明：

- 针对点/线/虚线/纲要重新生成、所有纲要模式、对齐和战斗的往返测试。
- 断言重试提示词收到与原始内容完全相同的原因和意图。

### F-12 — 中危：外部模式无限期推迟旧版迁移，且不提供可操作状态

证据：

必需修复：

- 为外部存储添加异步确认式迁移路径，或显示阻断性、可操作的协调状态。
- 绝不要静默选择任一副本。

## 重复与简化

### D-01 — 组合根仍然过大，无法安全审查

`index.js` 有 4,347 个物理行。它确实是一个组合根，但其中仍包含约 100 个顶层函数和大量行为，而不只是注册。当前工程文档称“约 4256 行”，该数字已过时。

不要机械地将其一分为二。应当：

1. 强制执行一项规则：不得向 `index.js` 添加新行为。
2. 仅在触及相关代码时迁移可独立测试的行为。
3. 将功能选项对象和事件注册保留在根中。
4. 添加自动化的文件大小/顶层函数预算，使增长清晰可见。

### D-02 — 四个聊天身份模块重复了相同机制

- `business/slip/identity.js`
- `business/law/identity.js`
- `business/space/identity.js`
- `business/outline/identity.js`

它们重复实现聊天 ID 规范化、修订版本规范化、冻结存储键构造和相等性判断。这种重复程度足以证明应创建一个职责狭窄的 `createChatScopedIdentity()` 辅助函数，同时保留领域特定的包装器和键名。

不要将剧场/坐标身份泛化到该辅助函数中；这些领域具有不同语义。

### D-03 — `runtime/refactor-adapters.js` 是一个内聚性较弱的工具抽屉

它混合了记忆标签合并、数据库备忘录检测、重投过滤、点后续决策、剧场模板过滤和剧场快照塑形。该文件名描述的是重构历史，而非稳定职责。

下次修改这些函数时，将其移至各自所属领域。不要再创建一个通用工具模块。

### D-04 — 设备偏好访问存在重复，且缺少失败契约

FAB 位置、面板位置/尺寸、纲要高度、剧场草稿、滑动层、诊断和迁移代码以不同错误策略访问浏览器存储。一个微型设备偏好适配器应统一：

- 解析/结构验证；
- 配额/安全失败行为；
- 易失回退标记；
- 键所有权；
- 涉及监听器/观察器时的拆卸。

该适配器不得用内存数据库取代聊天元数据或外部存储。

### D-05 — `createLinesFeature` 包含重复对象键和重复读取器

证据：

- `index.js:1587` 在顶层功能选项中定义 `readRaw`。
- `index.js:1631` 再次定义相同的顶层 `readRaw` 键。JavaScript 会静默地只保留后一个值。
- 等效的 `readStore(getLinesCacheKey())?.raw || ''` lambda 又在嵌套的注入、生成和操作环境中重复出现。

影响：

第一个属性是无效接线。重复对象键会降低审查可靠性，因为以后对第一次出现位置的编辑不会产生任何效果，也不会触发语法/测试失败。

措施：

- 定义一个 `readLinesRaw()` 辅助函数，并在所需位置注入。
- 如果引入 lint 工具，请添加静态重复对象键 lint 检查。

### D-06 — 侧边栏模式重置接线被反复复制

`index.js` 针对坐标、Slip、Law、Stage、Lamp 和相关侧边栏过渡重复了相同的多标志重置块（约位于 `index.js:1905`、`3146-3166` 和 `3396`）。

措施：

- 在模式状态附近创建一个命名明确且职责狭窄的 `resetSubViewModes()` 函数。
- 保持每个功能的实际进入/离开行为相互独立。

### D-07 — “将引文发送到 Space”导航存在两个近乎相同的实现

活动路径（`index.js:1422-1429`）和坐标路径（`index.js:2213-2219`）都会验证引文、离开当前向导、设置引文、打开 Space，然后再次设置引文。其中一个变体还会关闭 Activity。

措施：

- 提取一个导航辅助函数，并提供明确的可选 `closeActivity` 钩子。
- 在证明引文结构和意图语义完全相同之前，不要自动合并 Lamp 变体。

### D-08 — 规范书籍 ID 迁移接线存在重复

相同的 `migrateCanonicalBookIds()` 依赖对象同时出现在聊天切换加载（`index.js:2328-2334`）和首屏引导（`index.js:2375-2381`）中。

措施：

- 构建一次环境，并在两次调用中复用。
- 保留后期绑定的 getter，避免初始化顺序引入暂时性死区失败。

### D-09 — 线缓存键 API 声明了其忽略的参数

`getLinesCacheKey(view, charName)` 接受视图/角色参数，却始终返回 `keyDesc('lines', 'user', '')`。调用方可能合理地认为存在实际上并不存在的角色作用域。

措施：

- 如果线有意仅属于用户，请删除未使用的参数，并相应重命名调用方。
- 除非角色作用域存储是实际产品需求，否则不要添加它。

### D-10 — 通用文件名增加导航成本，但这些并非重复文件

仓库中有多个领域特定的 `snapshot.js`、`anchor.js`、`state.js`、`feature.js` 和 `identity.js` 文件。Windows 正斜杠/反斜杠搜索结果指向的是相同文件，而非文件系统中的重复副本。

措施：

- 仅在兼容性证据允许时，重命名真正含糊的根兼容垫片。
