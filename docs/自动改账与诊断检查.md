# 自动改账、诊断与手改：检查结论

日期：2026-09-14，现状复核：2026-09-16。对照 `运行逻辑与规则.md` §6.9、§8、§10。中高缺口和诊断改版已经落地，本文只把仍存在的低中优先级缺口留作后续路线依据。

验收一句话：**用户不用猜。打开【改】能看见这楼自动打算跑谁、谁跑了、谁跳过、谁失败、为什么、下一步点哪一颗。点不开的，本页编辑必须还能改回来。**

主干闭环已经可用；剩余缺口不会让本楼自动化静默失控，但少数入口仍需回原模块补救。

---

## 1. 已经齐的主干

本楼一条 AI 落地后，该跑的活进串行队列：

**对齐 → 推进 → 补录纪念日 → 刻度标注 → 刻度现状 → 面判定 → 冷知识**

一项失败不拦后面。楼过期（新 AI 楼、切聊天、关插件、时旅）才中止剩下的。

【改】同时回答三件事：

| 层            | 回答什么                                        | 用户能做什么                                     |
| ------------- | ----------------------------------------------- | ------------------------------------------------ |
| 本楼队列      | 这楼正在跑谁、接着谁、谁失败了                  | 失败胶囊单条重试；悬浮球红光                     |
| 节拍胶囊      | 对齐 / 推进 / 面 / 冷知识 / 补录 / 刻度最近一轮 | 点开看详情；可按结果撤回或重试                   |
| 最近 3 条卡片 | 改了什么、失败文案                              | 撤回 / 重试 / 拿到间里聊；滚点还能改成平移或再滚 |

对齐、推进这条主线最完整：成功进【改】、失败有文案、可撤（对齐只撤最新一轮）、可重试。换日没推上时有横幅「重试自动推进 / 手动推进到今天」。缺戳有横幅「手动补时间戳」。重 roll 会先撤这楼旧结果再按新正文重跑；你后来手改过、快照对不上，会挡住自动覆盖。

通知档：成功默认静默进【改】；`lite` 只吵你手点的；`full` 后台真改也报。

日常「对齐 / 推进没跑好」——打开【改】一般够用。

---

## 2. 当前闭环

### 点与线

- 换日滚点、按正文对齐和线推进的成功/失败会进入【改】；失败可重试，可撤的结果可撤回。
- 缺戳、API 未配置等软跳过会明确显示，不再伪装成本楼空闲。
- 点、线的单条编辑、锁定、删除和刷新入口仍在各自页面；同日重 roll 不撤已有推进是既定规则。

### 面、补录、冷知识与刻度

- 面判定、补录、冷知识、刻度的后台成功/失败都能落到队列或【改】；补录 0 条和无新刻度是 `unchanged`，不是失败。
- 手动刻度会进入【改】；节拍详情可按结果撤回或重试。
- 手改面游标会记【改】，快照还匹配才能撤回。
- 面/冷知识/刻度仍按整份快照撤回，点/线才支持按条撤回。

### 刷新账本与其它模块

- 刷新条在对账灯上：对齐会记录结果；重新生成按勾选模块逐块记下成功、没有变化或失败，失败可在【改】重试。打架一起改失败仍用原来的 `fight` 意图重试。
- 开局生成和点窗口补齐失败会进【改】；手改面游标留下可撤回记录，后来又改过则拒绝撤回。
- 间引导交给灯之后，改账结果记在灯/刷新那一侧；间自己不再写账，也没有「引导整卡撤回」。
- 棱、坐标、本轮拍、记忆不进入【改】，这是产品边界。

## 4. 你看到的「没有添加的（这很正常）」——正常

这句话几乎可以肯定是 **补录纪念日**，不是刻度标注。现在默认每 10 条 AI 楼补一次，不再每次换日。

自动 toast 原文：

> 通读全程后没有够格补录的新里程碑（这很正常）

历里已经有条目、且攒够间隔时，本楼队列会跑「补录」。它**只追加** anniversary / custom，自动锁定，最多 3 条，门槛很高：要够得上「明年还会专门记这一天」（立约、决裂、生死、身份转折这类），普通约会、同行、小胜负不够格。提示词写明：**通常 0–2 条，一条都没有是完全正常、甚至常见的结果，绝不能为凑数硬编。** `lite` 下自动补 0 条不弹这句 toast，只在【改】留记录。

所以：

| 你看到的                               | 含义                             | 要不要管                         |
| -------------------------------------- | -------------------------------- | -------------------------------- |
| 「没有够格补录的新里程碑（这很正常）」 | API 跑完了，0 条入库。**成功。** | 不用。真有大事再手点轴页爱心加号 |
| 「已补录 N 条纪念日」                  | 真补上了                         | 去轴页看一眼就行                 |
| 「补录失败，可在【改】里重试」         | 解析 / API / 保存坏了            | 要点重试或回轴页再补             |

注意：补 0 条**不写【改】卡片**，也不标队列失败。换日频繁时，你会反复看到这句 toast，这是设计，不是卡住。

历还是空的时候不会自动补录；第一次铺一年是轴页「生成节日」，另一件事。

## 5. 如果指的是刻度「老是没加新条」——也正常，文案不同

刻度标注（N 楼捞伤情 / 约定 / 周期）和补录不是同一件事。刻度空跑的文案是：

| 谁说的                 | 文案                                                                   | 何时                         |
| ---------------------- | ---------------------------------------------------------------------- | ---------------------------- |
| 模型按提示词只回「无」 | 【改】记「本轮刻度标注没有改动」；手动才 toast「未发现可登记的新事件」 | 近文里没有需要按时间盯的新事 |
| 模型报了，但都已在账上 | 手动 toast「没有新事件（都已在刻度上）」                               | 去重成功                     |
| 刻度现状无变化         | 【改】记「本轮刻度现状没有改动」                                       | 到期 / 现状都不用改          |

刻度只记「需要长期按时间追踪」的事，不记日常。大多数楼捞不到新条是预期。`lite` 下自动空跑不弹成功 toast，只在【改】留一条安静记录。

**不正常**的是这些：请先在设置中填写 API、刻度标注失败、格式无法识别、保存冲突。那些才该重试或手改。

账空、历史又很长时，自动标注**不会**默默开多批溯源，会请你点「立即标注」并确认——这也不是失败。

## 6. 编辑与纠偏入口

账记错了，各模块页面都能直接修改，不必等自动再跑一轮。【改】负责解释后台行为、重试失败和撤回可安全还原的结果；内容编辑仍留在拥有数据的模块里。

| 情况 | 最稳的入口 |
| --- | --- |
| 点没跟上正文 | 刷新条「按正文对齐」或【改】卡片重试 |
| 点窗口日期错了 | 点页「整体平移 / 滚动至今日」；【改】滚点条可改平移 |
| 线没换日 | 【改】重试 / 手动推进到今天；或线页推进 |
| 面游标没走 | 【改】重试自动判定，或面页手改节点 / 刷新条重做面 |
| 节日没补 | 【改】重试失败，或轴页「补录纪念日」；0 条是成功，见 §4 |
| 冷知识没抽 | 【改】重试失败，或线页新增 / 刷新条勾冷知识 |
| 刻度没标 | 【改】重试失败，或刻度页手动跑 |
| 整本生成不合适 | 刷新条填写理由后重新生成 |

纯手改面游标、开局生成/补窗口失败，以及刷新账本的块级结果已进【改】，见 §2 与 `路线图.md`。

## 7. 中高缺口（2026-09-14 已收）

1. 面失败、补录成败都写【改】；补 0 条是 unchanged。没配 API 的面/补录记失败。
2. 缺戳推进记 skipped + 本楼「跳过 · 缺戳」，不再假装空闲。

4. 最近 3 条可「查看更早」；失败卡带 `reasonCode`。
5. 重 roll 被手改挡住时，【改】列出哪些项没自动重跑。
6. 文档 §6.9 已改成现在真实能点到的入口。
7. 诊断改版见 §8：安全包 / 导出给助手 v2 已落地。

## 8. 设置里的诊断：当前方案

设置 → 存储与诊断 → **诊断管理** 已按两档隐私边界整理。目标是：**出问题后点一颗「导出给助手」，附上 JSON 和一两句现象，就能判断是没跑、跑空、解析失败、保存失败，还是规则本该如此。**

### 8.1 改版前的问题（设计背景）

| 块 | 实际内容 | 适合 | 发给我之后仍看不见 |
|---|---|---|---|
| **AI 输入** | 内存里**最近一次** `callApi` 的 `{ model, messages, outputLimit }`。刷新就没。 | 你自己对「刚才塞了什么」 | 哪一模块、哪一楼、模型回了什么、【改】/队列、开关 |
| **请求诊断** | 本机最近 30 条白名单 trace：`module / event / phase / reasonCode / errorClass / httpStatus / requestId / background`。无正文、无提示词、无 Key/URL。 | 公开发给任何人 | 模型看见/回了什么、账现在什么样、这楼队列是空闲还是跳过、【改】卡片 |
| **当前聊天诊断包** | 本聊天 `sp-store` 等根、最近 **2** 个可见 AI 楼的**每模块最新一次**请求（完整 messages + rawResponse + transport + result.events）、本聊天安全日志。可选附全文。不含 Key/URL/请求头。 | 给我看解析/保存 | 插件版本、自动化开关、本楼队列、【改】条目、没打 API 的跳过（缺戳、API 未配、补 0 条） |

所以：只丢「复制最近诊断日志」，我往往只能说「ledger-capture 在 parse 挂了」；不知道你开没开日期制、这楼有没有入队、【改】写没写、模型原文是什么。只丢诊断包，我能看提示词和原文，但经常还是猜「为什么没入队」。

诊断包已经比日志有用。缺口是：**运行时上下文**（版本、开关、锚点、队列、【改】）和 **没发请求的跳过** 都不在包里。

### 8.2 当前两档，不要合成一坨

隐私必须继续分档。Key / Base URL / 请求头 **永远不导出**。

```
诊断管理
  ├─ 本人核对（本地）
  │    最近一次 AI 输入（现有预览，可保留）
  ├─ 可以公开
  │    复制安全包  ← 改版后的「请求诊断」
  └─ 只发给助手
       导出给助手  ← 改版后的「当前聊天诊断包」v2
         · 不附正文（默认）
         · 附最近 2 楼正文（戳/解析类才勾）
         · 可选：我做了什么（一行，写进 json）
```

文案改短，避免「适合发给开发者」和「可能含剧情」两套说法打架：安全包写「无剧情」；助手包写「有账本和模型原文，只发给改这个插件的人」。

### 8.3 安全包（公开）要多带的运行时快照

在现有 30 条 trace 外包一层，仍禁止正文 / 提示词 / 回复：

```json
{
  "format": "st-sevendayscal-safe-pack",
  "version": 1,
  "pluginVersion": "3.8.0",
  "exportedAt": "ISO",
  "chat": {
    "floorCount": 12,
    "latestAiFloor": 11,
    "stampDay": "5-4",
    "axisToday": "5-4",
    "sameFloor": false
  },
  "settings": {
    "pluginEnabled": true,
    "linesEnabled": true,
    "linesMode": "days",
    "alignEnabled": true,
    "ledgerCaptureEnabled": true,
    "outlineJudgeEnabled": false,
    "dashedEnabled": false,
    "notifyMode": "lite"
  },
  "queue": { "floor": 11, "running": null, "queued": [], "failed": [] },
  "activity": [
    { "source": "advance", "outcome": "failed", "error": "…", "note": "", "floorId": 11, "items": [], "ts": 0 }
  ],
  "jobs": [
    { "id": "advance", "status": "skipped", "reason": "no-stamp" }
  ],
  "safeLogs": [ "…现有 30 条…" ]
}
```

`settings` 只收布尔和间隔，不要 API。`activity` 只要卡片头（source / outcome / error / note / floorId / items），**不要** snapshot / after 全文。`jobs` 是本楼「打算跑 / 跑了 / 跳过 / 失败」，专门补现在 trace 里没有的软跳过。

有这个，缺戳没推进、补录 0 条、面判定 skipped，我不用猜。

### 8.4 助手包（给我）= 现有诊断包 + 安全包那一层

`format` 升到 `st-sevendayscal-diagnostic-package` **v2**，在现有 `business / snapshots / diagnostics / safeLogs / narrative?` 上并入 §8.3 的运行时快照，并加上：

| 字段 | 为什么要 |
|---|---|
| `pluginVersion` | 对上当时的规则（换日滚点、这楼旧新戳） |
| `userNote` | 你写的「重 roll 了 / 期望推进没推」 |
| `chat.stampDay` / `axisToday` | 日期制一眼能对 |
| `queue` + `jobs` | 区分没入队、入队跳过、入队失败 |
| `activity` 最近约 8 条头 | 对上【改】你看见的 |
| 现有 `diagnostics.floors[].attempts` | 每模块最新一次 **完整输入 + 原始回复 + reasonCode** |
| 现有 `business` 根 | 点/线/面/历/刻度现在什么样 |

仍默认不附 `narrative`。戳解析、正文清洗、楼内框这类再勾「附最近 2 楼正文」。不要默认整串聊天。

保留「每模块每楼只留最新一次请求」——重 roll 后看的就是新戳那轮。若以后要查「旧戳 vs 新戳」，再加 `previousStampDay`（生成开始时已经有快照），不必存两轮全文。

`lastDebugPayload` 不必单独进包：助手包里的 attempt.messages 已经是那次输入；预览只留给你当场核对。

### 8.5 你怎么发给我

1. 出问题后尽快导出（换楼会清本楼队列失败态；重 roll 会覆盖该模块「最新一次」请求）。
2. 设置 → 诊断管理 → **导出给助手（不附正文）**。戳 / 清洗问题再选附正文。
3. 对话框里用一句话写：你点了什么、期望什么、实际怎样（会进 `userNote`）。
4. 把下载的 json 丢给我。不要只截「这楼后台空闲」。
5. 能公开的场合只发**安全包**。助手包有剧情和模型原文。

我读包的顺序（实现时按这个拼，也方便我拆）：

1. `userNote` + `pluginVersion` + `settings.linesMode`
2. `chat.stampDay` vs `axisToday`、`sameFloor`
3. `jobs` / `queue`：谁该跑、谁 skip、谁 failed
4. `activity`：【改】是否留下、文案是失败还是「没有改动」
5. 对应模块 `diagnostics.attempts`：`reasonCode` → rawResponse → messages
6. 必要时才翻 `business` 里的点/线/刻度原文

### 8.6 不做的

- 不把诊断包做成可再导入的备份（已有迁移包）。
- 不在【改】卡片上铺 `reasonCode`（那是 §7 的体验项；助手包带码即可）。
- 不把 Key / URL / 世界书全文默认打进安全包。
- 不把 24 条【改】全文快照塞进包（太大、也重复 `business`）。

落地顺序：先做助手包 v2（§8.4）和导出按钮文案，再收安全包快照（§8.3）。只做 v2 的话，你按 §8.5 发一份就够我干活。
