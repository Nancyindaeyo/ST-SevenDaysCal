## 1. 「间」的结构化卡片

### 原作者做了什么

出处：3.7.9。核心在 `business/space/context.js`、`schema.js`、`render.js`、`chat.js`。

- 「轴卡片／轴历卡片」默认当成**具体日期的历卡片**（`almanac_widget`）。
- 只有明确提到历法、纪年或月份结构时，才生成整套历法卡（`era_widget`）。
- 本轮生成会记住 `expectedWidgetKind`。
- AI 缺标签、错类或无效卡时，**原回复文字仍保留**；错类和混合回复里的额外卡不开放「应用」。
- 帮助提问与否定指令不误触发写卡。

### 我方现状

- `classifySpaceIntent()` 已有点/线/历/历法分流、帮助问、否定写卡、语义路由。
- **没有**「轴卡片 → 历卡片」的专词，也没有 `expectedWidgetKind`。
- 卡片已经改成只读建议：「交给灯 / 回间写清」，不再一键写账。见 `business/space/render.js`。

### 要不要合并

**不要整段合并。** 原作者仍把卡片当可应用账本补丁；我方已确认「间想、灯写」。把他们的 apply 白名单原样搬回来，等于撤回这条决策。

### 适合我们的适配

1. 只移植意图分类：`轴卡片 / 轴历卡片` → 历；明确历法结构 → 历法。帮助问、否定、引用例句继续走讨论。
2. 给本轮建议记住 `expectedKind`，供展示和「交给灯」使用，不恢复 apply 按钮。
3. AI 回错类或无效卡时，保留原文，并写清「这张建议不能交给灯」的原因。
4. 错类卡不得自动变成打架/对齐/重做意图。
5. 测试按行为写：轴卡片、历法卡、帮助问、否定、混合错类、无标签。不测源码正则。

不做：恢复「应用点/线/历/历法」、让间 `commit`、用原作者 `expectedWidgetKind` 当写账闸。

## 2. 线的剧情倾向

### 原作者做了什么

出处：3.7.9。独立文件 `business/lines/direction.js`。

- 按稳定角色键存在全局设置：`natural / positive / conflict / tragic`。
- 文案：自然发展、温暖向好、冲突增强、悲剧倾向。
- 进入线生成、线推进、「间」出线卡，以及开启后的线潜伏注入。
- 合同写明：只在同样有证据的候选里调优先级，不强制结果；可与成人模式并存。
- **不改线 schema。**

### 我方现状

- 没有 `direction.js`，也没有设置项。
- 线提示词和注入只有成人模式与叙事尺度。
- 设置已有按角色保存的成人模式，可复用同一角色键，不必另做身份系统。

### 要不要合并

**值得适配，不要整包合代码。** 这是作者偏好，不是第二套剧情账，也不和灯/【改】抢写账。体积小，和现有「证据优先、不编造」一致。

优先级放在剩余 P0/P1（笺/律草稿、机械 API fail-closed、活动历史确认写入）之后，可与「线休眠」并行设计，但不要和休眠混成一个字段。

### 适合我们的适配

1. 原样采用四值合同和「优先级而非强制结果」的提示词句子。
2. 按角色键写入 `extension_settings`，默认 `natural`，未知值回落 natural。
3. 接线生成、推进、线注入；间出线建议时也可带上，方便作者看到倾向。
4. 对账灯打架/对齐/重做**默认不改倾向**。倾向是作者预设，不是本轮补丁。
5. 不进稳定 ID、不进模型可改字段、不进可分享故事包的必选骨架。
6. 测试：默认 natural、四值归一、与成人模式并存、注入开启/关闭、切角色不串设置。

不做：让模型输出倾向字段、按楼自动改倾向、用倾向覆盖锁定线或已收束/淡出线。

## 3. 交互修复

### 原作者做了什么

出处：3.7.9。

- 悬浮球：`pointercancel`、`lostpointercapture`、位置 `localStorage` 失败仍结束手势；拖动后的 click 只拦截一次；阈值仍是 5px。
- 时间校准编辑行随面板宽度换行；保存/取消按钮 `flex-shrink: 0`，保持完整宽度。

### 我方现状

- `business/shell/fab.js` 已有 `pointercancel` 和 5px 阈值；`pointerdown` 会清 `dragged`。
- **没有** `lostpointercapture`，也没有把位置写入包进 try/catch。这与已记的 P1「设备偏好安全适配器」重合。
- 校准行只在 `max-width: 520px` 才换行，按钮没有禁止收缩。

### 要不要合并

**不当独立功能合并。** 这是宿主手势和窄屏排版，不是新模块。

### 适合我们的适配

1. FAB 的捕获丢失、存储失败收尾，并进 `runtime/device-preferences.js` 那条 P1，不要单独开「交互修复」PR。
2. 校准行改为随面板宽度换行，保存/取消不收缩。这是现有 UI 优化，不是新功能。
3. 拖动后误开面板：先在桌面/移动各点一次；只有复现再改 click 拦截。我方 `pointerdown` 复位可能已经够用。

不做：把原作者 `index.js` 里的 FAB 闭包搬回装配根；FAB 逻辑应留在 `business/shell/fab.js`。

## 4. 自定义历法

### 原作者做了什么

出处：3.7.10。自定义历法本身更早；这版补的是时间戳和越界显示。

- 主楼时间戳**另开一路**注入当前聊天的月名和每月天数（`buildStoryClockCalendarContext` + `STORY_CLOCK_CALENDAR_KEY`），不改用户自定义的时间戳提示词。
- 默认公历仍用原提示。
- 自定义历法日期越界：轴显示「日期待确认」；楼内日期回退到已确认合法锚点。不原样显示越界 raw，也不擅自推新日期。

### 我方现状

- 自定义历法（13 月、超 31 日、exact-or-unknown）两边都有。
- 点/线/面生成已用 `calendarLibraryBlock` 注入历法，但这是观察者上下文，**不是**时间戳那一路。
- 用户改过 `storyClockPrompt` 后，我方只注入用户全文，**没有**独立的现行历法块。
- `formatStoryClockMeta()` 在 `valid === false` 时回退 raw，自定义历上可能把越界日期显示成已确认。
- 楼内窄条在无合法 meta 时可能抬 raw，或按公历数字解析，冒充今天。

### 要不要合并

**不要合并整套历法。** 只适配两处正确性缺口：时间戳旁路历法上下文，以及越界日期的显示/回退。

### 适合我们的适配

1. 时间戳增加独立历法上下文 key。用户自定义戳词原样保留；有自定义历时再追加现行月名和日数。
2. 公历默认不追加这块，避免和内置 SDC 合同重复。
3. 轴上自定义历越界显示「日期待确认」，可保留星期和时刻；公历仍可显示旧 raw。
4. 楼内窄条在自定义历且戳不合法时，回退已确认锚点，不解析公历数字、不发明新日期。
5. 切聊天、关时间戳总闸时，历法上下文和戳词一起清掉。
6. 测试：自定义月名进入戳上下文且不改用户稿；越界轴文案；楼内回退锚点；公历 raw 兼容；无年不编造年份。

不做：用历法上下文改写用户戳词；越界时自动改锚点或改正文；把点/线生成的 `calendarLibraryBlock` 和戳上下文合成一块。
