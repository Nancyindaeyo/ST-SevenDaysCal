# 构画路线图

基线：**3.15.0**
复核日期：**2026-09-18**

本文只记录尚未完成的方向，不重复罗列已经落地的增量。优先级综合考虑用户影响、串聊天/写坏数据风险、实现成本和现有测试基础；它不是版本承诺。

现行行为见《[运行逻辑与规则](./运行逻辑与规则.md)》，【改】与诊断现状见《[自动改账与诊断检查](./自动改账与诊断检查.md)》，装配根怎么拆见《[index.js 拆分](./engineering/index拆分.md)》。

## 旧止损怎么处理

《运行逻辑》里那组「已知未做完」不再当待修清单。多数已经是产品边界或已经止损：

| 项 | 现在 | 还做不做 |
|---|---|---|
| 刻度没年 / 年环月日 | 有年走完整序差和真实加日；没年到期 unknown、滚周期只改年环。作者会碰到，写在运行逻辑 §6.8 | **不做**跨周期事务或假年推算 |
| 历法描述 + 节日两步写 | 已可确认写入；第二条失败回滚第一条并标 `almanac-save-failed` | **不做**跨模块 ACID |
| 点/线本地 `Id:` | 切聊天补一次，失败不覆盖；不进生成提示词 | **已落地**，继续不做进 prompt |
| 【改】面/冷知识/刻度整份撤回 | 点/线按条；其余没稳定条目身份 | **仍是 P2**，有身份再做 |
| 切聊天加载窗口旧潜伏注入 | 3.12.14 起边界开始同步清线/面/刻度/律注入，新聊天确认仍为当前聊天后才恢复 | **已落地**，保留 A→B→C 回归测试 |
| `index.js` 仍是装配根 | 可后移中块已迁完，根上剩下接线和注册表 | **维持装配根**，见第二节；不做全量框架重写 |

## 一、当前功能待优化方向

### P0：TT 虚拟化 ChatSurface 真机验收

3.8.1 已按宿主契约接上 `prepareContent` + `claim`、楼层按钮 `didMount` disposer；managed 模式不再用 MutationObserver / IntersectionObserver 猜节点归属，backfill 只重绘已经激活的投影。仍需要在真实 TT 打开虚拟化后走一遍挂载、滚动回收、切聊天和收藏钮。桌面 SillyTavern 的整串 DOM 不能代替这次验收。

#### 依据

- `runtime/chat-surface-participant.js`
- `business/inline/feature.js`
- `TauriTavern-main/docs/API/ChatSurface.md`

### P1：外置存储失败要明确

#### 方向

- 在纯 TT、无文件 API 或后端能力不完整时，设置页应明确显示“不支持/未就绪”，不能让用户误以为迁移已经成功。
- 切聊天加载、迁移、CAS 冲突、结果未知分别给出可行动的状态；未知结果不能静默重试覆盖。

#### 依据

- `runtime/external-chat-storage.js`
- `runtime/storage-panel.js`

### P2：面/冷知识按条撤回

- 面节点没有稳定条目身份，冷知识虽有 `id` 但撤回仍按整份快照；没有稳定身份前不发明按条撤回。
- toast 迁入 shadow root 以真实主题冲突或遮挡反馈为触发条件；目前没有这类报告，保持现状。

## 二、代码待精简或拆分

原则：一次只拆一个有独立语义的块；不改变行为，不把 `index.js` 对半切，不新增只有一个实现的万能抽象。新功能继续进 `business/` / `runtime/`，装配根只留 `createX({...})`。

`index.js` 现在大约 4256 行。可后移中块已经搬完，细节在《[index.js 拆分](./engineering/index拆分.md)》。根上剩下的是酒馆事件、feature 接线和跨模块 env，不是下一刀。

### 要不要用 Vue 重写

**不要全量重写。** 构画是酒馆页里的扩展，不是独立 SPA。已经拆开的 `business/` / `runtime/` 才是账本、切聊天、abort、owner guard；这些用 Vue 再写一遍不会变简单，只会把刚测过的边界重新打开。柏宝书那套 Vue + Shadow DOM 已经证明：`<Teleport to="body">` 会丢主题变量、弹窗被遮罩盖住。构画还要跟 jQuery、楼内框、ChatSurface、`messageFormatting` 和临时禁用 `regex` 共处，全量迁过去等于换一套宿主事故。

纯 JS + CSS 在这里是适配层，不是落后。仓内测试是 Node 跑 `*.test.js`，不经过组件挂载；全量 Vue 会逼测试去 mock 一整页，而当前缺口不在「模板字符串难看」。

可以以后谈、但默认不做的，只有 **局部新页**：某一块全新面板、状态几乎全是表单、和楼内生命周期无关，才允许用 Vue 挂进现有 shadow root。旧页不迁。业务层、store、生成、切聊天闸继续 vanilla。触发条件是「这块 HTML 字符串已经挡住交付」，不是「看起来更现代」。

### P1：下一刀（从最不缠宿主开始）

1. 不要再拆 `createLinesFeature` / `createActivityFeature` / `createPanelHost` 的 options 本身。
2. 线模块 Phase 2：只抽薄 swipe/CMR controller；出现状态漂移先补测试。

### P1：线模块 Phase 2

`business/lines/feature.js` 仍同时承担较多 generation、lifecycle、swipe/CMR 协调。下一阶段只抽薄 swipe/CMR controller：

- 保持单一 owner、chat revision 和 restore 规则。
- 一旦出现 swipe 状态漂移，停止继续拆分，先补契约测试。
- Phase 2 稳定前不做大规模 CSS/响应式重写。

### 每次拆分的门槛

1. 迁移前先确认目标块已有测试，缺失时补最小契约测试。
2. 每次只提交一块并运行 `node scripts/run-tests.mjs`。
3. 检查依赖方向：业务层不反向读取装配根，存储仍由 `store.js` / runtime 端口拥有。
4. 对生命周期改动额外验证切聊天与 abort；对数据改动额外验证 owner guard 和失败传播。

## 三、待新增功能

这些是候选能力，不代表已经排入版本。只有触发条件成立后才进入实现。工程项（1–2）和产品项分开列。

3.9.0 已落地 **笺**（侧栏私笺，永不注入）。3.10.0 已落地 **律**（侧栏短合同，勾选才进主楼）。3.11.0 已落地 **日台**（只读今日演出单）。3.12.0 已落地 **对账灯**（先是只读冲突，后改成冲突/搜索工作台；间出意图、灯写账）。3.14.0 已补提示词合同门禁、生命周期错误分级、可取消等待队列和本轮作者变更摘要。一起装着[柏宝书](https://github.com/Nancyindaeyo/ST-MemoryBook)时，**记忆摘要、物品、NPC、场景地图、计划/悬念、故事时间、好感估计**都归对方。构画已经只读配料（眼下地点、进行中计划、在场人物），不要再做第二套。构画继续管：日程窗口、历法、平行线、大纲、番外、顾问、刻度到期、作者私笺、聊天短合同、今日演出单、账本冲突与改账。下面只列柏宝书没有、或必须两本对起来才有意义的东西。

### 候选 1：多扩展 ChatSurface 协调

当构画、柏宝书或酒馆助手热重载同时存在时，用明确 owner/claim 协议避免同一楼重复登记、重复 observer 和重复投影。只有宿主契约稳定且真机验收通过后实施。

### 候选 2：线模块 Phase 3 响应式样式

在 Phase 2 controller 稳定后，为线页面和楼内线块补语义化 class、移动端布局和可测的状态样式。它不能与 lifecycle 重构混在同一版本。

### 候选 3：卷（面的篇章）

面是一串节点。长篇会变成几十个 Beat 一条绳子，作者想按「上卷 / 这一季」折叠。柏宝书的摘要森林是**已经发生的历史目录**；卷是**还没演完的大纲分组**。

- **触发**：面已经长到翻不动，你开始用节点标题当章名。
- **不是**：第二套记忆森林，也不自动按楼层切章。只给面加可折叠分组和游标落在哪一卷；生成仍写节点，不把卷名塞进稳定 ID。

### 候选 4：可分享故事包

现有迁移包会带设置（可能含 API Key）、本机草稿和坐标文件，适合自己搬家，不适合发给别人。故事包只打包点 / 线 / 面 / 轴 / 历 / 律 / 笺的账本骨架，去掉 Key、外置存储标记和设备草稿。

- **触发**：你真的要把同一套历法和大纲递给另一个作者，或换设备时不想把 Key 拷来拷去。
- **不是**：第二套备份格式，也不替代现有搬家包。导入仍只写构画自己的账，不碰正文和柏宝书。

### 候选 5：新聊天账本种子

新开一串聊天时，历法、律和面骨架往往要手抄上一串。种子是「从某串聊天或角色卡 extra 拷一份空账模板」：历法描述、律条文、面节点标题，不带日程窗口、不带记忆、不带间对话。

- **触发**：同一张卡反复开新档，每次都在重填历法和短合同。
- **不是**：开局自动生成点/线（那已经有排队）。也不把柏宝书 NPC/地图拷进构画。

### 候选 6：时旅足迹

时旅会改「今天」锚和落地楼，但没有一份能回看的跳跃记录。足迹只记：从哪天、落到哪一楼、落到哪天。允许点回上一次锚，不自动改正文。

- **触发**：你经常跳日，跳完找不到原来的「今天」。
- **不是**：时光机撤销生成，也不把足迹注入主楼。轴恢复仍然不改「今天」锚；回跳走单独确认。

### 候选 7：线休眠

线太多时，作者只想让几条暂时别进生成，又不想收束删除。休眠 = 这条线仍在线页、不进注入、不进日台「近日的线」，对账灯仍搜得到。

- **触发**：平行线已经多到互相抢窗口，你开始靠删线来减噪。
- **不是**：完成并删除，也不是第二套优先级分数。生成提示词仍然不放稳定 ID。

## 当前明确不做

- 不每楼自动重查点/线/面；继续使用节拍和手动入口。
- 不让本轮拍或间引导自动代发主楼。间不写账，灯才按提示词写。
- 不把棱合并为其它多媒体小剧场，也不自动绑定角色卡。
- 不把稳定 ID 放进模型提示词，不为此单独升级生成 schema。
- 不做小时级刻度或子日对齐；当前时辰只用于显示和上下文。
- 不为没年的刻度编造年份，也不做跨模块 ACID。
- 不为了压 token 再截断已经按规则保留的正文/记忆。
- 不把装配根拆分当新功能前置条件；重构与产品交付分别排期。
- 不重复柏宝书已有的物品、NPC、场景地图、计划/悬念、摘要时间线；需要时只读对照，不另建一本。
- 不用 Vue / React 全量重写现有面板、楼内框和生成链路。新页若用 Vue，业务层仍不迁。

## 建议顺序

1. 在打开虚拟化的 TT 真机上验收 ChatSurface 挂载/回收。
2. 线 Phase 2 只抽薄 swipe/CMR；不要为了 Vue 或「看起来干净」再拆装配根。
3. 外置存储失败态按出现顺序补齐；保留切聊天潜伏注入的延迟加载回归测试。
4. 面/冷知识按条撤回只在有稳定条目身份后启动。
5. 多扩展 ChatSurface 协调和线 Phase 3 只在对应触发条件成立后启动。
6. 卷、故事包、账本种子、时旅足迹、线休眠只在各自触发成立后启动，不跟拆分抢版本。
