# 构画（SevenDaysCal）运行逻辑和规则

给作者看的说明书：这套扩展在酒馆里实际怎么转、哪些会自动动、数据放哪。后面附走读代码时看到的问题。

检阅范围：`index.js` 装配根、`runtime/`、`business/` 主链路。这是静态走读，没有在酒馆里把每条路径点一遍。

当前清单版本：`3.7.7`，显示名「构画」。

---

## 1. 一句话它是干什么的

主楼还是你和角色在聊。构画不代写正文，只在旁边记账、纠偏、给主楼 AI 偷偷塞参考。

你可以把它想成七本账 + 一块仪表盘：

| 你在侧栏看到的 | 它管什么 | 它不是什么 |
|---|---|---|
| **点** | 从「今天」起近几天的日程 | 不是伏笔，也不是已经发生的历史 |
| **轴** | 历法、节日、纪念日、「今天」是哪天 | 不是日程本身 |
| **线** | 还在发展的平行事件 / 伏笔 | 不是当天待办 |
| **面** | 长线大纲（一串节点 + 游标「演到哪」） | 不是下一楼怎么写 |
| **间** | 局外顾问聊天；可以引导改点/线/面 | 不扮演、不代发主楼 |
| **棱** | 纯文字番外 | 不是兔子镜，不美化 HTML |
| **坐标** | 收藏楼层 / 摘抄 | 不进主楼提示词 |
| **改** | 最近自动/手动改了什么，能撤回 | 不是聊天记录 |

另外还有几块不住在侧栏第一排，但一直在转：

- **本轮拍**：卡住时给下一楼 4～5 条短大纲
- **冷知识**：世界观边角考据，住在线的子页
- **刻度（暗账）**：伤情、约定、周期这类要盯时间的事
- **记忆**：把旧楼压成摘要，生成点/线/面时当历史用
- **时间戳**：逼主楼 AI 在正文首尾打 `<!-- SDC-start -->` / `<!-- SDC-end -->`，构画拿它当「今天」

## 2. 数据存在哪

几乎所有「跟这串聊天走」的东西，都塞进这串聊天的 `chat_metadata`，会随聊天文件保存，换浏览器一般还在。

| 仓库 | 里面有什么 |
|---|---|
| `sp-store` | 点、线、面、间的对话、冷知识、历条目、历法描述、「今天」锚、本轮拍、最近改动、后台节拍倒数 |
| `sp-memory` | 内置记忆 L0/L1 |
| `sp-theater` | 棱的永久稿 |
| `sp-ledger` | 刻度账 |
| 设置（扩展全局） | API、开关、历法模板、世界书勾选 |
| 本机 `localStorage` | 棱草稿、少数设备相关缓存 |
| 坐标 | 走文件 API，是全局收藏，不跟单串聊天走 |

有外置存储模式时，上面这些会镜像到外置目录，切聊天会先加载再画界面。

点/线/面生成成功走「可确认写入」：切聊天时尽量不把旧聊天的结果写进新聊天。对齐补丁同样带开始时的 chatId 闸。

## 3. 插件启动之后发生什么

1. 读设置，挂字体和缩放。
2. 造出侧栏面板、悬浮球、记忆系统、坐标、各业务模块。
3. 向酒馆登记：聊天列表滚动时，给楼层挂「收藏」按钮和楼内框。
4. 监听酒馆事件（换聊天、AI 楼定型、重 roll、编辑、生成开始/结束……）。
5. 如果当前聊天已经打开（扩展加载时往往已经错过一次「换聊天」），立刻补一次迁移和楼内框。

关掉「插件总开关」：悬浮球和楼内框消失，后台任务掐掉，塞给主楼的提示词撤掉。设置面板还在，方便再打开。事件监听不会注销，只是各处先问一句「插件开了没」。

## 4. 一楼 AI 回复落地时，后台按什么顺序跑

酒馆先 `MESSAGE_RECEIVED`（正文到了），再 `CHARACTER_MESSAGE_RENDERED`（这楼画出来了）。构画的自动活几乎都挂在「画出来了」上，而且**同一层楼会按注册顺序连着跑**。

简化后的顺序：

```
AI 楼定型
  ├─ 时旅若占了这层楼：先卡住普通对齐和线推进
  ├─ 本楼队列 beginFloor
  ├─ 该跑的活先入队，再按固定顺序串行、各走各的 API：
  │    对齐 → 推进 → 补录纪念日 → 刻度标注 → 刻度现状 → 面判定 → 冷知识
  ├─ 一项失败：即使 lite 也 toast，【改】可单条重试，后面的继续
  ├─ 楼过期（新 AI 楼、切聊天、关插件、时旅）才中止剩下的
  ├─ 坐标按钮、楼内点/历条刷新
  ├─ 本轮拍同步当前楼
  ├─ 时旅自己的落地步骤（点按目标日重排 → 点/线按本楼对齐 → 轴刷新 → 面重定位 → 刻度）
  └─ 日期：有时间戳就直接读；换日才入队推进和补录（历里已有条目才补录）
```

同一楼可以排队干多件「改账」，不再「只干一件、欠下一楼」：

- **对齐和推进**：到期就都进本楼队列，先对齐再推进。日期制仍要这楼时间戳换了日才推进。
- **补录纪念日**：只跟**故事换日**走（时间戳落地 / 日期兜底）。轴面板 ±1、手改日期、时旅都不自动补录。线写成「只手动推进」时，换日仍可补录。历还是空的时候不补，第一次「生成节日」是另一件事。
- **冷知识**：到期就排在队尾，不再因为对齐/推进欠下一楼。
- **时旅那一层**：普通 N 楼对齐和线推进都不跑。落地后按**目标日**重跑点、按本楼正文对齐点/线、再刷新轴。不是按出发日把线往前推一格。

重 roll / 新 swipe 不当新楼：不占新的对齐间隔、不把线收成终态，对齐/面/冷知识/日期/刻度倒计时也不 +1。酒馆 regenerate 会先删最后一条 AI 再 push，下标碰巧还是同一个；各节拍共用 `sameFloor` 闸，GENERATION_STARTED 打标，本楼定型处理完再清。若这楼原本实际跑过自动对齐、推进、冷知识、面判定、刻度标注或刻度现状，重 roll / 切 swipe 会先撤回该项在这楼的旧结果（还能撤的话），再按新正文重跑；手动编辑楼不会触发。日期制仍会等这楼的时间戳落地，决定要不要按新日期推进，或把「不该推进」的撤回。失败会短 toast，并在「改」里留下记录。

## 5. 「今天」是怎么来的

全插件共用一个聊天本地的日期锚（`date-anchor`），不再失败时写回角色全局。

优先级：

1. **时间戳开着**（默认开）：每楼读正文里的 SDC 戳。读到月日就落地，不调 API。完整戳里的年、时辰也会写进锚点：年给跨年加减和刻度到期用；时辰只给轴/今头显示，格子和推进仍按天。
2. 读不到（漏打、只写了「谷雨」这种没月日）：若开了「日期兜底」，每隔 N 条 AI 楼问一次小模型。正文有年可以答 `YYYY年M月D日`，没有年不要猜。
3. 轴面板上你也可以 ±1 天、手改、恢复自动。有年时 +1/-1 走真实加日，可以跨年；没年仍走年环。

点页上的「周几」不是点模型写出来的。月日可以来自正文/柏宝书/点 StartDate；星期只认：完整时间戳、正文里紧贴日期的「星期×」、正文或柏宝书里的公历年月日（按真实公历推算）、或你手动校准。开局 0 楼常有「2024年8月31日」但没打时间戳，以前会显示「星期未记录」；现在有年月日就会算。不要用点里钉死的假年 2024 去 `getDay()`，那会和故事星期错位。点 StartDate 的 2024 只用来排格子月日，不进故事年。正文写了「星期日」但离日期较远时，以年月日推算为准（2024-08-31 是周六）。

锚点一变，会：

- 重画楼内历/点条、轴面板。**不再自动滚点删除。**
- 点页会自动定位并标出与时间戳相同的「今天」槽，不再把 Day 1 永远当今天，也不会因此改动事项。
- 若点窗口起点和剧情时间戳不是同一天，点页日期条上方会提供两种明确操作：「整体平移」会整体改日期标签，事项保持原槽位；「滚动至今日」会保留原日期，把过期事项归入「过去」，再补齐后续窗口。
- 若线是「故事日期变了就推进」，在这里检测换日

点窗口不够 3 天时，手动「推进」仍会先补缺的几天，再演化线。时旅落地仍可按目标日重排点。点/线按正文对齐走刷新条。

空账（还没有面、点、线）时，空页是「生成账本」：按 面 → 点 → 线 → 轴（没有节日才跑）→ 冷知识（总开关开着且还空）排队，一次一项。失败停在该项，前面已写入的保留。页头圆形刷新打开「刷新账本」并勾当前模块。

## 6. 各模块规则（人话版）

### 6.1 点（日程）

- 内容是从今天起往后几天 + 一个「未来」口袋。目标窗口是今天 + 后两天（共 3 天）。自动生成必须给出 Day 1–3，每天至少一条事项；只有日头没有事项会整次拒绝，不会存成「仅解析到两天」。已存档若某天是空的，仍占格子，避免后面几天顶到今天的日期上。
- 点窗口起点和剧情日期不一致时，可用 **整体平移** 一次改完日期标签；若不想让事项随标签改期，则用 **滚动至今日**，过期事项按原日期进入「过去」。
- 单条点可以编辑年/月/日/时间。改到窗口里另一天会挪格子；超出窗口进「未来」，并把月日写进时间。
- 「未来」生成时要求 time 带具体月日，不要只写未定。
- **锁定**：对齐默认不动；反馈里点名了标题才能动。
- **完成**：就是从当天删掉，不另做「已完成」栏。删除前标题会进「最近改动」。今天空了或不足 3 条时，下一次「按正文对齐」或【改】重试会按最新正文补当天名额，不会把刚做完的标题加回来。
- **推迟**：挪到另一天或进未来，不是完成。
- 生成走你配的主 API；机械对齐走同一套自定义 API（可把便宜模型分给机械任务）。【改】里的重试是再对齐，不是整表重做；正文没变且今天已满时，结果会和上一轮一样。

### 6.2 线（平行事件）

三条走法（设置 → 跟剧情走）：

| 模式 | 何时往前走 | 默认 |
|---|---|---|
| 故事日期变了就推进 | 时间戳/锚点换日 | 推荐，但新装总开关是「只在我点推进」 |
| 按楼数 | 每 N 条 AI 楼 | 不推荐和对齐叠用 |
| 只在我点「推进」 | 永不自动 | **新装默认** |

推进：还成立的未锁线演化阶段/下一步。不管对错。点窗口不够 3 天时，线页上的手动「推进」会先补点、再推线（两次 API 排队，不挤在一次请求里）。本轮有未锁活线进入收束/淡出时，同一次生成必须至少新建同等数量的非终态新线顶上（有正文依据，不为凑数编造）；没进终态时不强制补到 8 条。锁线终态不占自动池、不强制补。漏补则整次推进失败，可再点一次。日期制自动推进失败、或时间戳已经换日却没推上时，【改】里可以重试；另有「手动推进到今天」，只补还停在旧日的线，不走线页那种先补后天再一起演化。

对齐：走偏了才改（收束 / 暂缓 / 改描述）；点上今天空了或不足 3 条时，有正文依据就补当天。线的 complete 是收束，本楼先留着，下一楼才删；同一次对齐必须再 add 一条新线顶上。锁定线两边都默认不动。对齐不会补出新的点窗口天数。

`已爆发` 等终态不会再潜伏注入，也不会被自动推进当活线。刚收束/淡出的未锁线先留着展示；下一楼才删掉。删的时候不再另打 API，因为顶上的新线已经在上一轮推进里建好了。

超过 6 条的生成结果会整次拒绝，不会偷偷删你锁定的线。

关掉「线」总开关：生成、推进、注入都停。楼内线块由「楼内显示」单独控制。冷知识自动抽目前也被这条总开关误伤（见 bug）。

### 6.3 冷知识

- 默认关。开了以后按自己的间隔抽（默认每 6 条 AI 楼），取材近文边角，不是随机百科。
- 到期就排进本楼队列末尾，不再因为对齐/推进欠下一楼。
- 楼内最多留一句「补了一条，去线页看」。换一条用手点。
- 不注入主楼。写错了只勾刷新条的「冷知识」。
- 未锁条目会按保留条数清理；锁定的不计入数量、不删。

### 6.4 面（大纲）

- 一串节点 + 游标「现在演到哪」。
- 自动判定默认关：只把游标往后指，不重写正文。
- 刷新条重做面有三种：当前节点（默认）/ 续写 / 全部替换。自动判定和对齐都不会整份重写面。

### 6.5 轴 / 时旅

- 轴管历法模板、节日、将至。第一次「生成节日」会铺一整年；之后不要整表重做，用爱心加号「补录纪念日」往已有历里**穿插**新里程碑（只追加 anniversary / custom，自动锁定，最多 3 条，没有够格就 0 条）。补录会多喂近几层正文 + 全程记忆，不重铺节日。
- 时旅：你选一个目标日，构画让主楼演过去；落地后同步点、重定位面、处理刻度。线不作为时旅步骤直接生成，改走普通新楼通道。

### 6.6 间 / 引导

- 间是局外顾问，不写正式楼层。
- 引导可以勾选把草案落到点/线/面。没勾的模块不动，也不进「最近改动」。
- 引导成功不弹窗，只记「改」。

### 6.7 棱 / 坐标 / 本轮拍

- 棱：按正文一次出 1～3 条纯文字番外；篇幅跟模板/配方走，插件不再限字数。当前这篇可点「续写」（可选写接下来想看什么），另存一条续集草稿，原文还在。世界书只给棱抽，不绑到角色卡。喜欢的可导出一本新世界书。
- 坐标：收藏楼层快照和摘抄，可丢给间当引文。
- 本轮拍：侧栏单独一块，新一楼旧拍自然过期，不注入主楼。

### 6.8 刻度和记忆

- 刻度默认关。开了以后隔 N 楼捞新事件、再隔 M 楼刷现状。注入主楼另开。
- 内置记忆：每 5 条 AI 楼一篇 L0，每 10 篇 L0 一篇章节；最新那一组故意不总结，方便你重 roll。也可改用柏宝书当记忆源。

### 6.9 【改】

- 顶上先显示当前时间戳（最新楼 SDC 戳；没有则写明缺戳，并给出轴上的今天），方便对上剧情日期和点窗口。
- **本楼**：空闲 / 正在某项 / 接着排队谁。失败胶囊可点，只重试那一项。
- **节拍**胶囊：对齐 / 推进 / 面 / 冷知识 / 补录 / 刻度可点开看最近一轮。正在跑、排队、失败会叠在倒计时上。
- 每条旁边的小箭头关掉【改】，跳到对应页并滚到那一条；已经删掉的会提示「这条已经不在了」。
- 下面时间线只留最近 3 条。卡片操作只有撤回、重试、拿到间里聊。对齐、推进、补录、面、冷知识、刻度的失败记录都能重试。时间戳已经换日但自动推进没落下时，还会给出「重试自动推进」和「手动推进到今天」。线写成「完成并删除」时其实是收束，本楼还在，下一楼才拿掉。
- 悬浮球：后台推进中发霓虹光；有失败且没在跑时发红光。点开【改】看哪一项坏了。

## 7. 塞给主楼 AI（改模型行为，默认大多关）

总闸 `injectEnabled`，再加分项：

| 开关 | 默认 | 做什么 |
|---|---|---|
| 时间戳合同 | 开 | 每楼必须打 SDC 戳 |
| 线注入 | 关 | 把活跃线当 SYSTEM 塞进上下文 |
| 面注入 | 关 | 把当前/下一节点塞进去 |
| 刻度注入 | 关 | 把暗账塞进去 |

楼内框（你看见的折叠条）和注入是两回事。可以只看不塞，也可以只塞不看。

构画自己生成点/线/面/间/棱时，会另打一包上下文：人设、世界书（按当前聊天勾选 + 酒馆激活结果）、记忆、历法、可选近景楼。读近景/最后一层正文时：设置里「正文包裹」（默认 `content`）若在该楼出现，**只读标签内全文**，外面的状态栏丢掉，也不再截成 800/900/1600 字；没有包裹才走普通清洗。开着柏宝书时，还会加一段只读配料（眼下时间地点、进行中计划/悬念、在场 NPC），不对拷成点。世界书激活失败则这轮不塞世界书，并尽量只报一次。

## 8. 你自己点的那些

刷新条在点/线/面页共用：

- **按正文对齐**：只动勾了的点和线，不必填理由。今天空了或不足 3 条时，有正文依据会补当天；【改】重试走的也是这条，不是整表重做。
- **重新生成**：必须写「为什么刷新」；可勾点 / 线 / 冷知识 / 面；面可选当前节点、续写、全部。
- 线上的 **推进**：缺后天时先补点窗口，再演化已有平行事件。
- 【改】里的 **重试自动推进**：按当前时间戳再跑一遍日期制推进，不先补点窗口。
- 【改】里的 **手动推进到今天**：时间戳已经是新的一天、线还停在旧日时，只把线补推到今天；同样不走线页那种先补后天再一起演化。
- 点页日期条上的 **整体平移**：剧情已经是 5/1、点还从 4/30 开始时，把整组日期标签往后挪一天，事项保持原槽位，不跑 API。
- 点页日期条上的 **滚动至今日**：让 5/1 成为 Day 1，4/30 的事项按原日期进入「过去」，后续不足 3 天时再调用点生成补齐。

成功默认进「改」，失败才 toast。通知档：`off` 全静音 / `lite`（默认）只提醒你手动点的 / `full` 后台真改动也报。

撤回规则：用落地前快照一次性还原这次动过的模块。你后来又手改过，就拒绝撤回，避免把新编辑冲掉。

## 9. 切聊天时清什么

换聊天会立刻：

- 加一代「边界代数」，作废还在飞的旧任务
- 中止记忆、时旅、面、间、棱、冷知识、刻度、点生成、点/线对齐、本楼后台队列（失败红光一并清掉）
- 侧栏回到点页第一屏
- 加载这串聊天的外置数据 / 从本机旧缓存迁移
- 按这串聊天保存的节拍倒数恢复「还差几楼对齐/推进」

旧聊天飞回来的结果，点/线/面生成和对齐补丁都会尽量丢掉：对齐开始时记下 chatId，切聊天会 abort，写入前再对一次身份。

## 10. 这次已修的问题

原先走读清单里的条目已经按使用逻辑改过。摘要：

1. **对齐写错聊天**：对齐开始时记下 chatId，切聊天 / 关插件会 abort；写入带 `ownerGuard`。手动刷新和对齐互斥。
2. **时旅挡住对齐、没挡住线推进**：落地楼占住线模块，普通推进/N 楼对齐都不跑。时旅步骤改为：点按目标日重排 → 点/线按本楼对齐 → 轴刷新，再走面和刻度。
3. **关掉线总开关后对齐仍改线**：自动对齐不再勾线。冷知识改走 `onCharacterRendered`，不再被线总开关误关。
4. **模糊标题匹配**：先精确命中；模糊只在全表只剩一个候选时才用。空标题不匹配。点 `add` 超出日历天数进未来，不掉进第 1 天。
5. **日期失败缓存**：同一楼签名上失败/取消/未解析会重试；进行中和已有日期的成功结果仍复用。
6. **棱草稿保存失败**：`!saved?.ok` 即失败。本机 `ok: true` + `persistFailed` 仍算记忆里更新成功。
7. **面游标 `0`、引导写面、记忆封顶、冷知识近文条数、删楼记忆、暂停 toast、非法 linesMode、世界书缺字段**：按对应使用逻辑改过。`stagger.plan()` 生产仍未接线，时旅欠账改由上面第 2 条处理，不当成还开着的产品 bug。
8. **3.7.7 本楼串行队列**：对齐/推进/补录/刻度/面/冷知识先入队再按序跑；一项失败不拦后面。【改】能看见正在/排队/失败。悬浮球失败发红光。补录只跟故事换日走。

## 11. 建议你怎么验收

优先这几条：

1. 走一次时旅：落地那一楼线不应被 N 楼推进；点和线应按目标日/本楼正文重对齐，轴上的「今天」是目标日。
2. 开着点/线对齐，生成到一半切到另一串聊天，看新聊天的点和线有没有被旧补丁改掉。
3. 对齐跑着的时候点刷新条「重新生成」，应跳过而不是两路一起写。
4. 关掉「线」总开关、开着对齐，隔 N 楼线不应被改；打开冷知识仍可自动抽。
5. 日期兜底 API 失败后，同一楼再判定或时旅，不应一直沿用失败结果。
6. 删掉中间某条楼，覆盖它及之后的记忆摘要应丢掉。

补注：迁移遮罩「关闭」按钮在当前 `index.js` 总会带上 `onAbort`，生产里能点掉；模块本身若没传 `onAbort` 才可能卡死，不当成你现在会踩到的 bug。
