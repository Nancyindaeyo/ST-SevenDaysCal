## 1. 已锁定的需求

这些不要再翻案，也不要用「总上下文预算」把正文或记忆再砍回去。

| 项 | 约定 | 现状 |
|---|---|---|
| 刷新账本 | 手点「按正文对齐 / 重新生成勾选项」。不进本楼自动队列，不跑推进 / 补录 / 刻度 | 已是 |
| 最后一楼正文 | 有「正文包裹」就只读标签内**全文**，不再截 800 / 900 / 1600 | 已是（`extractStoryText`） |

| TT 主路径 | 按你现在的设置：**虚拟化关**。虚拟化打开后的投影回收，以后再说 | 方向见 §4 |

## 2. 提示词现在还「少喂」什么

不再有硬编码 tk 封顶。还在按**条数**少喂的，都不是截最后一楼正文：

| 闸 | 做什么 | 会不会弄丢本楼正文 |
|---|---|---|
| `historyLimit` | 近景楼：多数 3、对齐 5、补录 12、冷知识自动 0 | 不会。最后一楼另走 `latestStory` |
| 正文包裹 `keepTags` | 默认 `content`：包裹外状态栏不读 | 包裹内不截字 |
| 记忆 L0 / L1 分组 | 每 5 楼一篇 L0，每 10 篇 L0 一篇 L1 | 摘要节奏；开柏宝书则整条停 |
| `memorySkipShort` 50 字 | 太短的 AI 楼不进内置 L0 | 只影响内置记忆 |
| 扫时间戳 40 楼 | 只找 SDC 戳 | 不进生成 prompt |
| 冷知识保留 / 避开 | 未锁最多 15；生成避开最近 12 | 管冷知识库 |

世界书真正的闸是**激活关键词 + 你在构画里勾选 / 排除的书**，不是 tk 预算。角色书 + 少量全局，按你的用法够用。

## 3. 优化建议（先记着，不急着做）

1. **不要再发明一把「总预算」回头砍正文。** 上下文变贵时，先排世界书排除、柏宝书召回范围、`historyLimit` 楼数。正文和本轮拍的最新楼保持全文。
2. **世界书变长时用排除列表，不要恢复 60000。** 谁家卡挂了十几本全局再另说；你现在的量不需要硬顶。
3. **`recall.js` 的抽块算法可以以后删。** 生成已不走，留着只是对照。
4. **虚拟化关着时，楼内框比虚拟化开着更吃内存。** 每一楼的 DOM 都在。若以后长聊卡顿，优先把**活框**限制在近 N 楼（远处只留快照或坐标钮），不要为此打开虚拟化。
5. **本楼队列保持串行。** 一次只打一个自定义 API，比并行更适合 iOS WebView。刷新账本「重新生成」也是一项一项来，不要改并行。
6. **打开【改】/ 设置时不要扫全部楼层正文。** 现在大体如此，以后加功能时守住。
7. **字体 URL 失败就退系统栈。** 慢网时不要挡住首屏。
8. **间·引导 / 棱的字数闸**和本楼不是一类问题。等你觉得引导也「读不全」再动。

## 4. TT / iOS：按你的设置慢慢做

前提：虚拟化关、本楼队列已串行、ChatSurface 已登记、投影不假发 `CHARACTER_MESSAGE_RENDERED`、iOS toast 已打标。

虚拟化关 = 聊天 DOM 还是整串在，楼内框 / 坐标钮主要走现有挂载，**不必先做 `prepareContent` + `claim`**。那套是给「投影会扔 DOM」用的。

### 现在就够用、出问题再补

- 悬浮球、面板、toast 和 TT 底栏 / 键盘抢层
- 拖球 / 拖面板以 touch 为准
- 继续用自己的对话框，不用 `alert` / `confirm`
- 切聊天、关插件要 `abort` 本楼队列和在飞请求
- 账本跟聊天走，不把 localStorage 当跨设备源
- 不要为「楼又画出来了」重跑对齐

### 以后有空再做（虚拟化仍关）

1. 长聊时近窗活框、远处空壳（§3.4）
2. 打开【改】只画当前队列，不扫全文
3. 外置存储在纯 TT 上缺文件 API 时，提示失败，不要装成功
4. 和柏宝书、酒馆助手热重载共存：不要重复登记 ChatSurface

### 明确后做（你打开虚拟化之后）

投影回收、`claim`、禁止在 `prepareContent` 里开异步 / 观察器、backfill 不要一次挂几十楼。你现在关着，这些先不排期。

### 明确不做

- 不为投影伪造 `CHARACTER_MESSAGE_RENDERED`
- 不把本楼自动活和刷新账本并成一条队列
- 不把世界书 / 记忆 / 近景楼绑成总预算再砍正文
- 不按「打开虚拟化」来验收你的日常用法
