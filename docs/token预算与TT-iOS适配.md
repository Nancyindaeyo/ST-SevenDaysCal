## 2. 提示词现在还「少喂」什么

不再有硬编码 tk 封顶。还在按**条数**少喂的，都不是截最后一楼正文：

| 闸 | 做什么 | 会不会弄丢本楼正文 |
|---|---|---|
| `historyLimit` | 近景楼：多数 3、对齐 5、补录 12、冷知识自动 0 | 不会。最后一楼另走 `latestStory` |
| 正文包裹 `keepTags` | 默认 `content`：包裹外状态栏不读 | 包裹内不截字 |
| 记忆 L0 / L1 分组 | 每 5 楼一篇 L0，每 10 篇 L0 一篇 L1 | 摘要节奏；开柏宝书则整条停 |
| `memorySkipShort` 50 字 | 太短的 AI 楼不进内置 L0 | 只影响内置记忆 |
| 扫时间戳 40 楼 | 只找 SDC 戳 | 不进生成 prompt |
| 冷知识保留 / 避开 | 未锁最多 15；生成避开最近 12 | 管冷知识库 |

世界书真正的闸是**激活关键词 + 你在构画里勾选 / 排除的书**，不是 tk 预算。角色书 + 少量全局，按你的用法够用。

## 3. 优化建议（先记着，不急着做）

1. **不要再发明一把「总预算」回头砍正文。** 上下文变贵时，先排世界书排除、柏宝书召回范围、`historyLimit` 楼数。正文和本轮拍的最新楼保持全文。
2. **世界书变长时用排除列表，不要恢复 60000。** 谁家卡挂了十几本全局再另说；你现在的量不需要硬顶。
3. **虚拟化关着时，楼内框比虚拟化开着更吃内存。** 每一楼的聊天 DOM 都在，但构画投影只维护近窗：从末尾收最近 N 层 AI 楼，进视口才挂 DOM。200 楼基线见 `business/inline/near-window.js`。不要为此打开虚拟化。
4. **本楼队列保持串行。** 一次只打一个自定义 API，比并行更适合 iOS WebView。刷新账本「重新生成」也是一项一项来，不要改并行。
5. **打开【改】/ 设置时不要扫全部楼层正文。** 卡片和本楼队列只读活动存储；时间戳横幅最多回看近 40 楼。
6. **字体 URL 失败就退系统栈。** 慢网时不要挡住首屏。
7. **间·引导 / 棱的字数闸**现与点/线摘录同档 1600。主楼正文和本轮拍仍不截。

## 4. TT / iOS：按你的设置慢慢做

前提：本楼队列已串行、ChatSurface 已登记、投影不假发 `CHARACTER_MESSAGE_RENDERED`、iOS toast 已打标。

虚拟化关 = 聊天 DOM 还是整串在，楼内框走近窗 + IntersectionObserver。虚拟化开 = `#chat > .mes` 是可丢弃投影，楼内框走 `prepareContent` + `claim`，坐标钮走 `didMount` disposer，不再用 observer 猜节点。

### 现在就够用、出问题再补

- 悬浮球、面板、toast 和 TT 底栏 / 键盘抢层
- 拖球 / 拖面板以 touch 为准
- 继续用自己的对话框，不用 `alert` / `confirm`
- 切聊天、关插件要 `abort` 本楼队列和在飞请求
- 账本跟聊天走，不把 localStorage 当跨设备源
- 不要为「楼又画出来了」重跑对齐
- 打开虚拟化后在真机上验收挂载 / 滚动回收 / 切聊天

### 以后有空再做

1. 外置存储在纯 TT 上缺文件 API 时，提示失败，不要装成功
2. 和柏宝书、酒馆助手热重载共存：不要重复登记 ChatSurface

### 明确不做

- 不为投影伪造 `CHARACTER_MESSAGE_RENDERED`
- 不把本楼自动活和刷新账本并成一条队列
- 不把世界书 / 记忆 / 近景楼绑成总预算再砍正文
- 不按「关闭虚拟化」来验收打开虚拟化后的投影回收
