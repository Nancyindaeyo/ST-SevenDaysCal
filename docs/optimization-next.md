# 下一轮产品需求（整理稿）

日期：2026-09-16。第四轮拍板已落地；现行行为以《运行逻辑与规则》和《[prompts.md](./prompts.md)》为准。

作者主要在 TT iOS。刷新账本继续手点、串行、不进本楼自动队列。柏宝书只读对照，不回写。

---

## 0. 一句话

**间负责想清楚，灯负责按对的那份提示词改账。** 点 / 线 / 面 / 轴 / 刻度 / 冷知识是账本页。日台是今天看什么。【改】是审计和重试（重试还是原来那份提示词）。

间聊到最后**可以**出一份给灯跑的东西，而且应该出。但那份不是把间的整段对话或顾问 system prompt 复制过去——那会把打架 / 重试 / 重做三套模板搅在一起。间产出的是 **改账意图**（人能读、灯能填进自己的模板）。灯选对的机器提示词再跑。

## 2. 现在哪些是混乱的（先认账）

同一本账现在有多条「谁都能写」的路，提示词还不完全是一职一份。

### 2.1 谁都能改点 / 线

| 入口 | 实际提示词 | 写不写账 |
|---|---|---|
| 刷新条「按正文对齐」 | `buildReconcilePrompt`（纠偏补丁） | 写点和线 |
| 刷新条「重新生成」 | 各本生成 prompt + `buildRefreshAddon`（reason/feedback） | 写勾中的点/线/冷知识/面 |
| 设置里 N 楼自动对齐 | **同一套** `buildReconcilePrompt` | 写 |
| 【改】重试对齐 | 再跑对齐，**应该**仍是 reconcile | 写 |
| 【改】重试刷新失败 | `regenerate({ reason: '【改】重试这次失败的刷新' })` | 写，但 reason 被换成这句，**原「为什么刷新」丢了** |
| 间·引导「确认写入」 | `buildGuideDraftPrompt` → 整份 widget | 写点/线/面 |
| 间·聊天里的点/线/历 **卡片 + 应用** | 聊天 system + widget 合同 | 写点/线/轴 |
| 点/线页「和间聊聊」 | 跳去间聊天 | 间再走上面两条 |

灯还不写账。间已经能写。刷新条和间引导、间卡片是三套写手。这就是乱。

### 2.2 提示词已经混用的地方

- **对齐**和**打架一起改**若都去调用 `buildReconcilePrompt`，会变成「跟正文对齐」和「只改列出的打架项」抢同一份模板。打架必须是**单独**的提示词（见 §4）。
- **重试**必须重跑**当初那一种**提示词 + 当初那份意图。现在刷新失败重试会丢掉原 reason。
- 间聊天可以吐 `schedule_widget` / `line_widget` / `almanac_widget` 并一键应用：顾问和写账在同一个输入框里。
- 间引导只落地点/线/面，刻度/轴/冷知识只能口头建议，作者不知道「确认写入」改了哪几本。
- 本轮拍、刷新条挤在点/线/面顶上，和「改这本账」不是同一件事。

### 2.3 这一轮要收成的职责

```
想 / 聊 / 出草案     → 间（不写账）
选条目 / 手改 / 跑改  → 灯（唯一的「按提示词改多本」入口）
改单本内容           → 点线面轴刻度冷知识页（手改仍可用）
看今天演什么 + 下一拍 → 日台
看改了什么、失败重试 → 【改】（重试 = 原提示词，不换套）
```

## 3. 提示词一职一份

灯跑改账时，只允许下面几种 **kind**。间不发明第五套跑法。

| kind | 谁点 | 用哪份提示词 | 动什么 |
|---|---|---|---|
| `align` | 对账页「按正文对齐」 | 现有 `buildReconcilePrompt` | 未锁点/线，跟最新正文 |
| `fight` | 对账页「按打架一起改」 | **新**的打架提示词 | 只动待改篮里的条目；六本都可以点名；面默认当前节点；轴禁止整年重铺 |
| `regen` | 对账页「重新生成勾选项」 | 各本原生成 prompt + addon | 勾中的模块整段重做 |
| `retry` | 【改】重试 | **当初那条**的 kind + 意图，一字不改套 | 与失败那次相同 |
| `hand` | 灯/各页编辑键 | 无 API | 手改字段 |

意图只填进模板里的「为什么 / 写错了什么 / 要动哪几条」，**不替换**上面的骨架。

间同意后交给灯的，是意图，不是 `buildSpaceChatSystemPrompt` 全文。

## 4. 间两套，最后出意图给灯

### 4.1 纯聊天

局外顾问。贴引文、直接问、讨论设定。**这一套不写账。**

（现有聊天「应用点/线/历卡片」和这套冲突，见 §8。）

### 4.2 草案 → 意见 → 意图 → 灯

单独一个键，例如「出改账草案」，不要跟发聊天混在一个纸飞机里。

1. 带着灯贴来的引文（待改篮条目）问间：哪里不一致、建议改哪几条、改成什么。
2. 用户提意见，间改草案，可多轮。
3. 用户点「同意，交给灯」。间把草案收成 **改账意图**（人话清单，不是模型 system prompt），例如：

```
跑法: fight
要动: 点, 刻度
条目:
- 点「合宿闭幕式与物资清退」：描述里的伤势改成已能小幅度抬起、可签字；地点仍是宿舍楼大厅
- 刻度「星野南右臂挫伤」：现状改成夹板已拆、弹力套、酸痛大幅缓解
不要动: 面整份, 轴整年, 未点名的线
依据: 柏宝书只对照，不改对方
```

4. 跳回灯·对账页：待改篮按意图勾好，意图全文出现在「为什么 / 写错了什么」里，跑法已经是 `fight`。用户还能改勾选，再点「按打架一起改」。
5. 灯用 **打架提示词** 跑，意图当 addon。跑完记【改】。失败重试仍用 `fight` + 同一份意图。

这就是各司其职：间不碰 store；灯不负责想剧情对不对。

### 4.3 为什么「复制提示词给灯」要收成意图，不要原文粘贴

更好，但粘的必须是意图。

- 间的聊天 prompt 含顾问人设、世界书、记忆、卡片合同。丢进灯会让打架模板失效。
- 灯必须自己喂最新点/线原文和最新楼正文。间草案里的账快照可能已经过时。
- 重试要对得上 kind。自由粘贴的长 prompt 无法标记这是 fight 还是 regen。

## 5. 对账灯两个子页

### 对账

- 冲突列表（启发式灯）。行程当天多地不当打架。
- 待改篮：冲突 ∪ 从查找勾过来的 ∪ 间意图点名的。
- 每条：编辑（全字段弹窗）、移出篮子。
- 折叠：刷新条（对齐 / 重做勾选项）。主按钮是「按打架一起改」。
- 若有一份未跑的间意图，显示在篮上方，可「用这份跑」或丢掉。
- 柏宝书原文只展示。
- 「拿到间」：把篮子做成引文，跳到间（只贴引文；可选直接问）。

打架一起改覆盖点、线、刻度、轴、冷知识、面。串行。只改点名条目。

### 查找

- 本地关键词，不打 API，不搜笺。
- 结果按本分组。每条：勾选、编辑、单条拿到间。
- 勾选后底栏：加入待改篮（转到对账页）、拿到间、全选本次查找。
- 相关 ≠ 打架。不勾就不进篮、不跑 fight。

手改字段（两页同一套弹窗）：

| 本 | 灯里要能改 |
|---|---|
| 点 | 标题、地点、年/月/日、时间、描述、线头 |
| 线 | 名称、时机、阶段、描述、下一步 |
| 面 | 标题、场景 |
| 轴 | 名、类型、月日、说明 |
| 刻度 | 事由、类型、现状、牵扯、标签、到期（保存仍上用户锁） |
| 冷知识 | 正文（现在只能锁/删，要补） |

## 6. 日台

- 标题完整换行；时间/地点/状态第二行。
- 下面本轮拍：空着折叠，有拍展开。生成/改/复制/填输入框/新楼清空不变。
- 间若「顺手出本轮拍」，toast 打开日台并展开拍。

## 9. 做不到、或这一轮不该做

| 想法 | 原因 |
|---|---|
| 把间的整段顾问 prompt 复制给灯当 system | 冲掉打架/重试/重做骨架 |
| 间同意后直接写六本账 | 间没有六本补丁格式；写账归灯 |

| 在灯里改柏宝书 | 对方的账 |
| 【改】重试用打架模板去重试对齐失败 | 必须原 kind |

点标题/地点、线名称/时机、冷知识正文：现有编辑器缺字段，灯里补，做得到。

## 10. 建议落地顺序

1. 日台字看全 + 侧栏置顶 + 本轮拍搬家（与提示词无关）
2. 补录 10 楼；棱导出；坐标配方
3. 灯两个子页 + 待改篮 + 手改弹窗 + 查找勾选（还没接新提示词）
4. **先写打架提示词**，和对齐 / 重做 / 重试分开测
5. 一起改接刻度/轴；修多地误报
6. 间：引文 + 草案键 + 意图回灯（8.1 / 8.2 拍板后再动旧的应用/引导写入）

## 11. 验收（实现时）

1. 点/线/面没有刷新条；日台标题看全，底下有拍则展开本轮拍。
2. 灯能在对账 / 查找之间切；勾选进篮；能手改标题和时间。
3. 打架跑的是 fight 模板；【改】重试打架失败仍是 fight，不会变成对齐模板。
4. 间同意后灯上能看见意图清单，点跑才改账；间自己不写 store。
5. 换日不连跑补录；第 10 楼才自动补。
6. 棱导出只有形式并进模板堆；坐标能折叠看配方。
