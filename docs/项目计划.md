# 构画（ST-SevenDaysCal）完整审查与实施计划

> 基线：3.15.8
> 审查日期：2026-09-25
> 范围：`index.js`、`store.js`、`memory.js`、`api/`、`runtime/`、`business/`、`style.css`、现行 `docs/` 与契约测试

## 1. 结论

构画已经不是一个简单的“日程生成器”，而是围绕 SillyTavern 正文维护多本剧情账的作者工作台：

- **点**管理近期日程；
- **线**管理仍在发展的平行事件；
- **面**管理长线大纲和当前游标；
- **轴**管理历法、节日、纪念日和剧情日期；
- **刻度**追踪伤情、约定、周期等时间状态；
- **日台 / 对账灯 / 改**分别承担驾驶舱、冲突与搜索、审计与恢复；
- **间 / 棱 / 坐标 / 笺 / 律 / 记忆 / 本轮拍**补齐作者咨询、番外、收藏、私笺、短合同、历史压缩和下一拍。

代码已经有较强的聊天边界、任务 owner、确认写入、串行队列和契约测试基础。当前不适合全量框架重写，也不应把所有模块合成一个“万能剧情系统”。下一轮应先修明确的数据与费用风险，再补真机验收和可观察性，之后才做新功能。

## 2. 已验证基线

- 规模：318 个生产 JS、140 个测试文件、22 个 `business/` 领域目录。
- 大文件：`index.js` 约 4500 行（`index.budget.js` 口径；预算 4550 行 / 220 个顶层函数），`style.css` 8354 行。
- 自动化：`node scripts/run-tests.mjs` 为 **830/830 通过**。
- 工作树原有改动：仅 `docs/engineering/index拆分.md`，本计划不覆盖该改动。
- 浏览器/真机：Chrome DevTools 连接不可用；没有验证真实 SillyTavern 页面、TT iOS 或 ChatSurface 虚拟化。

## 3. 当前明确缺陷与逻辑风险

### P0：冷知识“自动清理”报告成功但没有删除数据（已修）

证据：

- `business/lines/dashed.js:73-75` 的 `pruneDashedItems()` 正确返回 `items` 与 `removed`；
- `business/lines/dashed.js:171` 的 `cleanup()` 已算出 `preview.items`，却调用 `commit(current)` 再次提交裁剪前数据；
- 随后仍 toast“已清理 N 条”并返回 N，形成假成功。

影响：超过保留数的未锁冷知识持续累积；UI 与存储不变，但用户被告知清理成功，违反 `docs/运行逻辑与规则.md` §6.3。

实施：

1. 提交 `preview.items`，或直接让 `commit(current)` 的实际结果成为唯一计数来源，避免双算。
2. 只有写入成功且重读条数符合预期才提示成功。
3. 增加 `cleanup()` 行为测试：未锁条目裁剪、锁定条目保留、关闭清理、写入失败。

### P0：【改】可能在撤回落盘失败后仍标记“已撤回”（已修）

证据：

- `business/activity/feature.js:46-52` 的整份 `restore()` 不检查各 writer 返回结果；
- `business/activity/feature.js:158-167` 的按条撤回只等待 Promise，不验证 `ok / stale / commitState`；
- `index.js:1362-1370` 的点/线 writer 调用了 `writeStoreConfirmed()`，但丢弃其返回值；
- 随后活动记录仍写入 `undone: true` 或 `undoneRefs`，并触发恢复成功 UI。

影响：外置存储失败、聊天边界变化或确认写入被拒绝时，真实账本没有恢复，【改】却显示已撤回，破坏审计可信度。

实施：

1. 统一 writer 合同为 `{ ok, stale, commitState, reason }`；布尔旧实现通过适配器显式转换。
2. 整份恢复按固定顺序执行并收集结果；任一失败时不标记完整撤回。
3. 按条撤回只记录实际确认成功的 ref；失败项保留可重试状态。
4. 写入后重读关键指纹，确认账本与目标快照一致。
5. 增加点/线/面/冷知识/刻度写入失败、部分成功和切聊天测试。

### P0：笺 / 律在切聊天时可丢失最后 400ms 输入（已修）

证据：

- `business/slip/feature.js:35-43`、`business/law/feature.js:48-57` 将输入延迟写入；
- 两者的 `onChatChanged()` 都先取消定时器，再清内存；
- `runtime/chat-changed.js:25-26` 直接调用这两个清理入口；
- 当前测试明确断言切聊天后“不写入”，证明这是现行行为，不是未覆盖猜测。

影响：用户刚输入笺或律就切聊天，最后一小段文本会静默丢失。律还可能出现“屏幕上刚改过，但实际注入/存档仍是旧版本”的短暂错觉。

实施：

1. `scheduleSave` 保存 `{ text, inject, targetIdentity }`，而不是只保存闭包。
2. 聊天边界前尝试对冻结目标做确认写入。
3. 宿主不能写旧目标时，将内容放入明确的“可恢复草稿”，提示用户恢复，不静默丢弃。
4. 不允许用当前聊天的普通 `writeStore` 假装写回旧聊天。
5. 添加 Slip/Law 对称测试：确认成功、目标已切换、确认失败、恢复草稿、注入清理。

### P1：机械任务预设失效时静默改走主 API（已修）

证据：

- `runtime/settings.js:155-167`：预设不存在或 URL/key 不完整时直接 `return loadCfg()`；
- `runtime/api-presets-ui.js:99-106` 只在设置页渲染时清理悬空 ID；
- `api/client.js:361-372` 的记忆摘要等机械调用直接消费该配置。

影响：用户本来把机械任务路由到便宜模型，预设损坏后会无提示使用主 API，造成费用与模型行为变化。

实施：

1. `loadUtilityCfg()` 返回带状态的结果，例如 `configured / follow-main / invalid`，不要把 `invalid` 折叠成成功回退。
2. `invalid` 默认 fail-closed：机械任务暂停并留下可操作诊断。
3. 设置页提供三种显式动作：修复预设、明确允许临时走主 API、关闭机械任务。
4. 【改】和诊断包记录实际模型路由与降级原因，但绝不导出 key。
5. 覆盖预设被删、缺 URL、缺 key、模型为空、用户明确回退等测试。

### P1：【改】活动历史仍使用非确认写入（已修）

证据：`index.js:1338-1347` 为活动存储注入普通 `writeStore()`；失败虽会提示“记录可能消失”，但没有固定聊天目标和确认提交状态。

影响：账本改动已经成功，刷新后对应审计/重试记录可能缺失；切聊天或外置写入并发时尤其难以解释。

实施：活动记录绑定 chat identity，通过确认写入或同一 metadata 确认队列持久化；记录失败不能回滚已成功的业务改动，但必须保留可恢复的最小失败标记。

### P1：设备偏好存储缺少结构校验和失败边界（已修）

证据：

- `business/shell/fab.js:3-12` 只做 JSON 解析，不验证有限数值；
- `business/shell/fab.js:84-87` 的等待型 `MutationObserver` 没有持久引用，热重载时无法主动释放；
- `business/shell/fab.js:106-120`、`business/shell/window.js:77-81,139-145,177-210,284-301` 直接访问 `localStorage`；
- 现有测试仅覆盖损坏 JSON，没有覆盖合法 JSON 中的非法类型、存储异常和观察器销毁。

影响：禁用存储、配额异常或污染值可中断拖动/缩放收尾；`NaN`、字符串、极端坐标可能把窗口放到不可见位置；热重载可能留下等待观察器。

实施：

1. 新建窄职责 `runtime/device-preferences.js`，仅承载窗口位置、尺寸、折叠状态等设备偏好。
2. 对数字执行 `Number.isFinite`、范围裁剪和 schema 归一化。
3. 读写异常返回显式易失状态，不影响交互收尾。
4. 追踪并在 `dispose()` / 热重载时断开观察器与定时器。
5. 不得把聊天账本、确认写入失败或外置数据塞入该适配器。

### P2：刻度重评分错误被静默吞掉（已修）

证据：`runtime/st-listeners.js:178-184` 对 `refreshLedgerInjection` 和 `refreshInlineWindow` 使用空 `catch`。

影响：刻度注入或楼内框刷新失败时，用户只会看到旧显示，诊断包缺少失败原因。

实施：保留“后续监听器继续执行”的 best-effort 语义，但必须写脱敏 trace；连续失败时在诊断管理显示一次，不应每楼 toast。

### P2：用户可见元数据与现行能力不一致（已修）

- `manifest.json:5` 仍把对账灯描述为“只读冲突”，但 3.15.0 已是冲突/搜索/预览/写账工作台。
- `docs/engineering/index拆分.md:3` 仍写约 4256 行，当前为 4310 行。
- `docs/自动改账与诊断检查.md:85` 与现行“unchanged 是否进入【改】”表述需要按代码再次统一。

实施：修代码风险时同步更新 manifest、README 索引和现行文档；历史审计保留原结论，但清楚标记“已修复/仍开放”。

## 4. 不是当前 bug、不要误修的边界

- 没有故事年时，刻度到期为 unknown，是避免编造年份的产品规则。
- 历法描述与节日不是跨模块 ACID 事务；当前两阶段确认与回滚已经是明确折中。
- 点/线稳定 ID 不进模型提示词，避免模型复制或篡改内部身份。
- 面、冷知识、刻度目前按整份快照撤回；稳定身份不足前不要硬做按条撤回。
- 间负责讨论和产出意图，对账灯负责按正确提示词写账；不要恢复“间直接 commit”。
- 刷新账本保持手动、串行；不要塞入每楼自动队列，也不要为了速度改成并行 API。
- 不恢复统一 token 硬上限去截断最新正文、记忆或已选世界书。
- 不以 Vue/React 全量重写现有宿主接线、楼内框和生命周期。

## 6. 当前功能可优化部分

### 功能

- **点**：提供窗口完整性检查，明确“缺 Day / 空天 / Future 缺日期”的具体原因。
- **线**：增加休眠状态；休眠线不注入、不进日台，但仍可搜索和恢复。原作者 3.7.9 的剧情倾向值得另做：按角色保存四档优先级，不改线 schema，不对账灯默认改倾向。
- **间**：只移植「轴卡片=历 / 历法结构=历法」分类和本轮 `expectedKind` 展示；错类建议保留原文并拒绝交给灯。不恢复一键写账。
- **轴 / 时旅**：增加时旅足迹，只记录起止日期和落地楼，不自动改正文。自定义历越界时轴显示「日期待确认」，楼内回退已确认锚点；时间戳另注入现行月名/日数，不改用户自定义戳词。
- **面**：先引入稳定节点身份，再做按条撤回与“卷”分组。
- **对账灯**：Dry Run 与写入 diff 复用现有补丁解析，不另建第二套生成逻辑。
- **改**：保留跨楼失败、原始 retry payload、当前锁定差异和未知提交状态。
- **存储**：外置模式明确区分“不支持 / 未就绪 / 冲突 / 未知结果”。
- **诊断**：加入最后确认写入时间、机械 API 实际路由、四路注入摘要与恢复草稿状态。
- **记忆**：保持最新组延迟总结；补充“清洗后为空”的设置定位指引。
- **备份**：把自用迁移包与可分享故事包严格分开。
- **首次使用**：提供可跳过的“推荐跟剧情”配置向导，解释默认手动模式，不暗改现有用户设置。

### UI

- 将当前最小约 9.28px 的字号令牌重新分级；80% 缩放下不能出现约 7.4px 的正文/关键状态字。
- 为所有主要动画补统一 `prefers-reduced-motion`，当前只覆盖少量成人内容过渡。
- 完成侧栏 tab 的键盘方向键、Home/End 和焦点可见性；图标按钮补一致的 aria-label。
- 短屏设置页增加固定的当前位置/返回顶部，减少多层 `<details>` 导航成本。
- 移除点/线/面中仅用 CSS 隐藏却仍留在 DOM 的旧刷新按钮，或彻底改向对账灯入口，避免焦点落到不可见控件。
- 对账灯子 tab 补 `aria-selected` / `aria-controls`；本轮拍等图标按钮补 `aria-label`。
- 【改】、对账灯和设置统一空态、失败、跳过、未确认四种视觉语义。
- 时间校准编辑行随面板宽度换行，保存/取消按钮不收缩。
- 对移动端触控目标设置最小尺寸，避免 9–11px 图标文字与窄按钮难点。
- 保留 Shadow DOM 与现有主题令牌；不把弹窗 Teleport 到 body。
- CSS 拆分前先做视觉回归样例：日/夜、ST 自定义主题、桌面、窄屏、TT 安全区。

## 7. 未来新增功能候选

按建议顺序：

1. **可分享故事包**：只包含点/线/面/轴/历/律/笺骨架，剔除 API key、设备草稿和外置标记。
2. **新聊天账本种子**：复用历法描述、律、面标题，不复制日程、记忆和间对话。
3. **时旅足迹**：可回看日期跳跃并确认恢复锚点。
4. **线休眠**：降低长篇并行线噪声。
5. **线的剧情倾向**：按角色保存自然/向好/冲突/悲剧，只调优先级，不改 schema。详见 `docs/原作者3.7.9对照.md`。
6. **卷**：给面节点增加折叠分组，但不替代记忆森林。
7. **跨扩展 ChatSurface 协调**：宿主契约和 TT 真机通过后再做 owner/claim 协议。
8. **故事健康检查**：本地检查缺戳、窗口不完整、悬空 ID、失效预设、未知提交；不请求模型、不自动写账。

明确不新增第二套 NPC、物品、地图、摘要森林或计划/悬念系统；这些继续由柏宝书拥有，构画只读对照。

## 8. 每个改动的统一门槛

1. 先写可观察行为测试，不测试源码字面量。
2. 数据改动必须覆盖 owner guard、确认写入、失败和 unknown commit。
3. 生命周期改动必须覆盖切聊天、关插件、热重载和在途请求。
4. 提示词改动必须覆盖最小/典型/超长样例、机器标记和 token 报告。
5. 运行 `node scripts/run-tests.mjs`，要求 0 失败。
6. 运行所有已跟踪 JS 的 `node --check`、`git diff --check`、manifest JSON 解析。
7. 涉及宿主/UI 的版本必须完成对应真机矩阵，不能只用 Node 测试批准发布。
