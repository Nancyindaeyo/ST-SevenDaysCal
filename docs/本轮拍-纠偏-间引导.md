# 构画增量需求（CURRENT）

更新：2026-09-09（三）。实现以本文为准；前文讨论已合并。代码在 `src/ST-SevenDaysCal-master/`，版本约 3.6.9.1。

本文不是已完成功能说明。

## 0. 作者怎么玩

主楼是两段，不是让构画代写正文：

1. 先给本轮大纲（导演稿；工具箱里可以是 `{GLOBAL:…}`，本轮拍不强制这个格式）。
2. 主楼 LLM 按人设长肉。

卡住时缺的是「下一拍怎么写」。正文走偏时，点/线/面会过期或写错。番外在棱里看，喜欢的做成**新世界书**再导进兔子镜。

模块对照（构画现状，刷新勾选按这个分，不要混）：

| 模块 | 是什么 | 不是什么 |
|---|---|---|
| 点 | 从「今天」起的近几天日程 | 不是平行事件，也不是冷知识 |
| 线 | 仍在发展的平行事件 / 伏笔 | — |
| 冷知识 | 线的子页（虚线），世界观边角考据 | 不是点；默认关，要单独勾选才生成 |
| 面 | 长线大纲 | 不是本轮导演稿 |
| 间 | 局外顾问 | 不写正式楼层、不扮演 |
| 棱 | 纯文字番外 | 不是兔子镜，不美化 HTML |
| 本轮拍 | 下一楼的 4～5 条短大纲 | 不送去棱 |

平行事件写错了，刷新的是**线**。冷知识写错了，单独勾**冷知识**。点写错了，才勾**点**。

## 1. 要做 / 不要做

**要做**

- 棱：纯文字，不再走 HTML 美化。按正文一次出 1～3 条，每条约 1500 字；数量可设，上限 3。
- 三本小剧场世界书导入酒馆，棱勾选挂载。读条目时**内置剥除**交互 / HTML / CSS / JS / 超长字数 / `<snow>` 外壳，只留可写的纯文字配方。
- 喜欢的勾选后导出**一本新世界书**（母本提示词），作者再导进兔子镜。不是把小回/极光/小兔原样再导一遍。
- 点 / 线 / 冷知识 / 面手动刷新：勾选才动；一个「为什么刷新」输入框；一个可选「上次哪些写错了」反馈框。
- 点/线自动纠偏：每 3 条 AI 楼（不计 user），结束后 toaster。默认关。
- 本轮拍：卡住时 4～5 条短大纲。不填棱。
- 间引导：只收束点/线/面。不问番外、不填棱。

**不要做**

- 每楼检查点/线/面。
- 本轮拍或引导结论自动注入主楼、代发用户楼。
- 自动重写整份面（引导正式生成且用户勾了面除外）。
- 间里的话直接改账本（除非引导里勾选落地）。
- 把兔子镜并进构画；读兔子镜内置 208 种形式；给兔子镜加扫描/自动请求。
- 把成品问卷/IF 全文当兔子镜母本。
- 把三本原书整本当兔子镜外部母本。
- 三本挂到角色卡上当主楼激活世界书（否则每轮正文后都会插剧场）。
- 棱再做第二套 HTML 美化 / 交互装置。

## 2. 棱：纯文字番外

### 2.1 生成

点「生成」→ 读当前正文（可加点/线/面作配料）+ 挂载世界书抽到的配方 → **一次请求**出 1～3 条纯文字。默认 2 条。不调用美化 API，不输出 HTML/CSS/JS。

每条篇幅统一约 **1500 字**（问卷、一百问、IF 都按这个收，不再跟原世界书的 6000 字走）。可空输入：空则只靠正文和抽签。三条尽量不同条目，不要同构续写。

显示用构画自己的纯文本卡片（可折叠）。不要 `<snow>`，不要兔子镜 `<toto>`。

### 2.2 挂载世界书 + 内置剥除

作者把书导入酒馆，棱设置里多选「抽取用世界书」。建议三本都可以挂，由棱剥除，不必因极光是交互就默认禁用。

`写卡/小剧场/` 现有三本：

| 书 | 原合同 | 棱怎么剥 |
|---|---|---|
| 《小回剧场纯文字随机版》-春 | 必开头/尾 + group 抽类型；禁 HTML；要 `<snow>` 折叠 | 留下类型说明（一百问、回望、聊天记录…）；丢掉 `<snow>` / details /「每次正文结束后生成」这类主楼插入指令 |
| 极光小剧场-随机版 | HTML+CSS+**JS** 深度交互 UI | 丢掉全部布局、动画、JS、滚动条、媒体查询；只留「这是什么玩法、角色在这个装置里做什么」 |
| 小兔的小剧场合集 2.0 | 一条一个沙雕/IF 大纲，常要全文 HTML 和 6000 字 | 留下故事前提和硬限制；丢掉美化句、字数下限 |

公共剥除规则（对所有挂载书）：

- 删：HTML/CSS/JS 要求、`<script>`/`<style>` 示例、交互组件规范、`<snow>`/`<toto>`/`<details>` 外壳、主楼「正文结束后插入」、6000 字这类篇幅命令。
- 留：条目标题、体裁（问卷/IF/日记/聊天记录…）、剧情前提、人物与禁忌、不 OOC。
- 字数一律改成约 1500 字，丢掉原书里的 6000 字之类下限。
- 「使用必开 / 开启 / 头 / 尾」：不当抽签候选项；其中的纯文字规范（禁 HTML、禁重复）并入本次 system。其余条目按世界书 `group` 组内抽签，一次抽 N 条。
- 剥完若只剩空壳，跳过该条再抽。

不要把这些书激活到当前角色。只给棱读。现有 `构画-棱-小剧场模板` 仍可手写，与挂载书并存。未挂书时按正文自行想形式。

### 2.3 喜欢 → 导出一本新世界书 → 兔子镜

每条结果可勾选「喜欢」。成品留在棱草稿/永久保存里读。

「导出已选」生成**一本新书**，例如 `构画-棱-兔子镜母本.json`（或写入同名酒馆世界书）。每条喜欢的作品最多两条目：

| comment | key | content |
|---|---|---|
| `展现形式｜相性100问` | `展现形式`, `问答`… | 以后怎么再出这种体：结构、题量、口吻、禁忌。不要贴本轮答完的题 |
| `主题｜体检前夜的亲密` | `主题`, 两三个词 | 这一季气味与关系，短，不剧透全文 |

标题带「展现形式」「主题」，方便兔子镜分类器认。作者用兔子镜「外部世界书母本」选本地 JSON 或酒馆已有书导入。新库默认停用，需确认分类并打开外部抽签。构画不代开兔子镜、不写它的 IndexedDB。

## 3. 点 / 线 / 冷知识 / 面：手动刷新

现有「刷新」太粗：点是未锁整表重做，线是推进或重生成，面是整份替换，没有「我为什么刷」也没有「只动其中几块」。

### 3.1 共用一条刷新条

放在点/线/面都能看到的地方（面板顶或各页复用同一块），不要三个互不相通的刷新。

```
勾选本次要动的：
[x] 点（日程）  [x] 线（平行事件）  [ ] 冷知识  [ ] 面
                    [全选]

为什么刷新（必填或强烈建议）：
「剧情不满意，我想改成…… / 平行事件写成了 A，实际是 B」

上次哪些设定可能写错了（可选）：
「点把体检写成了今天；线把柳当在场；冷知识把立海校规写反了」

[按正文对齐]     [重新生成勾选项]
```

- **不勾选的模块本次完全不写 store。**
- **全选** = 四个都勾。
- 冷知识和线分开勾：只觉得考据错了就不要动平行事件。
- 锁定条目：刷新时仍按现规则保留锁标题；用户在反馈里点名要改的锁，提示先解锁。

两个按钮不要合成一个：

| 按钮 | 做什么 | 什么时候 |
|---|---|---|
| 按正文对齐 | 纠偏补丁：完成/推迟/改描述，不整表洗牌 | 正文走偏了，账本过期 |
| 重新生成勾选项 | 按「为什么刷新」+ 可选反馈，重做勾选模块 | 剧情方向不对、设定写错、想推倒重来 |

「为什么刷新」在点「重新生成」时应有内容（可允许很短）。「按正文对齐」可以不填，但填了就当额外约束（例如「不要把推迟的体检删掉」）。

可选反馈框每次生成都带上：明确写错的事实，新结果必须避开或改掉，不要沿用。

### 3.2 自动纠偏（另一条路）

手动刷新不替代后台对齐。

- 每 **3** 条 AI 楼一次（不计 user / system），间隔可改，最小 1。
- 只动点 + 线（未锁）。冷知识、面不自动重写。
- 必须带最新 AI 楼正文。
- 没偏也可以 toast 一句「点/线与正文一致」；有偏说明改了什么。`notifyMode = off` 仍弹短提示。
- 独立开关，默认关。时旅占闸的楼跳过。
- 与线「回合制推进」同楼冲突时：本楼已纠偏则跳过自动推进。

补丁类型：已发生则从今天拿掉或标完成 / 推迟则挪走或 stall / 换路径则改描述留标题 / 证据够才新建 / 没偏不动。

## 4. 本轮拍

独立入口。读纠偏后的点/线、面当前节点、间近期发言、近文。一次出 **4～5 条**短大纲：这一拍发生什么、落到什么结果。可改、可复制、可填主楼输入框。不代发，不填棱。

四条拉开差：演完今天的点 / 一条线侧面进来 / 外部日期压力 / 纯日常 / 间里刚说的方向（没有则「换路径、留面节点结果」）。

默认手动。纠偏 toast 可带「查看本轮拍」，点了才生成。

---

## 5. 间引导

保留自由聊天。空态或「引导设计」：给我灵感（可换一批）/ 我来描述。问答围绕角色、剧情、节奏；选项 + 自定义 + 跳过；上一步 / 下一步 / 重置 / **不用问了**。

不用问了之后：先一段 AI 理解，再出点/线/面草案。每块：保持 / 按草案改 / 我写意见 / **不用你想**。确认后才写入正式账本。不问番外，不填棱。可选顺手出本轮拍。

---

## 6. 和兔子镜

棱负责纯文字番外 + 导出新母本。兔子镜负责视觉成品。不合并、不互调内部 API。

主楼用户楼里的大纲，兔子镜跟随正文时本来就会读到。

---

## 7. 实现顺序

1. 棱：关掉美化；一次 1～3 条纯文字；挂载世界书；剥除交互/HTML。
2. 棱：勾选喜欢 → 导出一本新世界书 JSON。
3. 点/线/冷知识/面共用刷新条：勾选 + 为什么刷新 + 可选写错反馈；「对齐」和「重新生成」分开。
4. 自动纠偏每 3 条 AI 楼 + toast，默认关。
5. 本轮拍。
6. 间引导。

新代码不要再堆进 `index.js`。

---

## 8. 设置草案

推进

- 点/线按正文自动对齐（默认关）
- 每 N 条 AI 回复对齐一次（默认 3）

棱

- 一次数量 1～3（默认 2）
- 每条约 1500 字
- 抽取用世界书（多选；小回/小兔/极光都可挂，靠剥除而不是禁用极光）
- 无「HTML 美化」开关：本增量里棱固定纯文字

刷新条属于面板，不另做总开关。

---

## 9. 现有债（做增量时顺手或随后）

1. 线自动推进不带本楼 → 纠偏必须带；推进可选手动含本楼。
2. 面判定绑死 `outlineInject` → 拆「只推游标」和「注入主楼」。
3. 默认线每 2 楼推进，和「先写本轮大纲」不一致 → 新装可改为手动或更大间隔。
4. `index.js` 约八千行；测试几乎不在本 fork。
5. 间空窗；通知默认 lite 时后台改账不说话。
6. 不要把这些书挂到角色卡。

## 10. 后定

- 点「已完成」是单独状态还是直接移出今天。
- 面「重新生成」勾选后：整份替换 vs 只改当前节点及后续（优先增量）。
- 本轮拍入口放顶栏还是面页。
- 刷新条「为什么刷新」重新生成时是否硬必填（建议有内容即可，不设很长下限）。
