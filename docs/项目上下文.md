# 构画（ST-SevenDaysCal）项目上下文

> 用途：给后续开发、审查和 AI 协作提供稳定上下文。
> 当前基线：3.15.8（2026-09-25：侧栏竖排不折列、摘抄不截字、手机点选后可摘抄）

## 1. 产品定位

构画是注入 SillyTavern 的第三方扩展。它读取聊天正文和剧情时间，维护作者侧的剧情账本，并把用户明确允许的部分作为 SYSTEM 提示注入下一楼。

它不替用户发送主楼正文，不把所有信息揉成一张时间线，也不负责柏宝书已经拥有的 NPC、物品、地点、摘要森林和计划/悬念账。

核心概念：

| 概念 | 领域含义 | 主要模块 |
| --- | --- | --- |
| 点 | 从“今天”开始的近期日程窗口 | `business/point/` |
| 线 | 尚在发展的平行事件、伏笔 | `business/lines/` |
| 面 | 长线大纲、节点与当前游标 | `business/outline/` |
| 轴 | 历法、节日、纪念日、今天锚点、时旅 | `business/axis/`、`business/calendar/` |
| 刻度 | 伤情、约定、周期等时间状态 | `business/ledger/` |
| 间 | 局外顾问，产出讨论与改账意图 | `business/space/` |
| 棱 | 纯文字番外 | `business/theater/` |
| 坐标 | 楼层收藏与摘抄 | `business/coordinate/` |
| 笺 | 当前聊天作者私笺，永不注入 | `business/slip/` |
| 律 | 当前聊天短合同，勾选后才注入 | `business/law/` |
| 日台 | 今日驾驶舱，只读汇总 | `business/stage/` |
| 对账灯 | 冲突、搜索、预览和改账工作台 | `business/lamp/` |
| 改 | 自动任务、改动、失败、重试与撤回 | `business/activity/`、`business/refresh/` |
| 本轮拍 | 下一楼短大纲，不注入主楼 | `business/beat/` |
| 记忆 | 内置 L0/L1 历史摘要或柏宝书历史 | `memory.js`、`business/memory/` |

## 2. 技术形态

- 语言：浏览器原生 JavaScript ESM，无 `package.json`、无 TypeScript、无构建步骤。
- UI：jQuery + 字符串模板 + Shadow DOM；楼内投影仍进入聊天 DOM。
- 样式：单文件 `style.css`，同时服务 Shadow DOM 主窗口和 light DOM 楼内块。
- 宿主：直接导入 SillyTavern 的 `extensions.js`、`script.js`、`world-info.js` 等内部模块。
- 测试：Node 内置 test runner，入口 `node scripts/run-tests.mjs`。
- 当前测试基线：827 项通过。

不要把“没有构建步骤”误认为没有架构。当前架构通过工厂函数和环境端口隔离宿主、业务与纯函数。

## 3. 架构分层

### 3.1 装配根

`index.js` 是 composition root：

- 导入宿主 API 与领域模块；
- 创建 feature/controller/host；
- 注入跨域端口；
- 挂 jQuery 启动；
- 注册 SillyTavern 事件；
- 保留少量必须晚绑定的闭包，避免 TDZ。

约束：允许保留大的 options 接线对象，不允许再把新业务算法写回根文件。当前约 4500 行（`index.budget.js` 口径，预算 4550 / 220），行数本身不是拆分目标。预算测试守门，超了先迁走行为。

### 3.2 运行时适配层

`runtime/` 负责宿主与跨领域生命周期：

- `settings.js` / `settings-bind.js` / `api-presets-ui.js`：设置与 API 路由；
- `st-listeners.js`：酒馆事件处理与注册；
- `chat-changed.js`：聊天边界清理、加载、迁移、恢复；
- `generation-context.js`：聊天边界 epoch 与延迟回调作废；
- `plugin-lifecycle.js`：总开关、中止、注入清理和错误分级；
- `target-metadata-save.js`：固定目标确认写入；
- `external-chat-storage.js`：外置 BaiNiaoData、CAS、迁移与快照；
- `chat-surface*.js` / `inline-host.js`：TT 虚拟化与楼内投影；
- `world-info-*.js`：世界书筛选、激活和设置 UI；
- `diagnostic-*.js`：脱敏 trace、运行摘要、导出包；
- `backup*.js`：迁移包；
- `device-preferences.js`：本机 FAB/面板位置尺寸与大纲聊天高度；棱草稿和 swipe 缓存仍留原模块。

### 3.3 业务领域层

`business/<domain>/` 按领域放 schema/codec、repository、prompt、controller、feature、UI。业务模块不应反向读取 `index.js` 状态，跨域能力通过 `env` 注入。

不要因为多个目录都有 `feature.js`、`state.js`、`identity.js` 就合并；它们属于不同 bounded context。笺 / 律 / 间 / 面共用 `business/chat-scoped-identity.js`，但各自保留包装器和键名；棱和坐标不要接到这个 helper。

### 3.4 数据与 API 层

- `store.js`：`sp-store` 统一聊天账本、普通写入与确认写入；
- `memory.js`：`sp-memory` L0/L1 摘要；
- `business/ledger/repository.js`：`sp-ledger`；
- `business/theater/`：`sp-theater`；
- `api/client.js`：主 API、机械 API、SSE、重试、超时和诊断；
- `api/diagnostics.js`：错误分类与可恢复 UI 效果。

## 4. 启动与事件主链

### 4.1 启动

1. 读取扩展设置，应用主题、字体和缩放。
2. 创建 Shadow DOM 面板、悬浮球、领域 feature 和 runtime host。
3. 注册楼内框、坐标按钮和 ChatSurface participant。
4. 通过 `runtime/st-listeners.js` 绑定命名事件监听器；重复绑定会先移除旧监听器。
5. 若扩展加载时聊天已打开，补聊天迁移、注入和楼内投影。

### 4.2 AI 楼落地

`CHARACTER_MESSAGE_RENDERED` 上的关键顺序：

1. 时旅预检先占自动化闸。
2. `beginFloorAutomation` 建立本楼身份。
3. 各 handler 判断节拍并入队。
4. `business/refresh/floor-queue.js` 固定顺序串行：
   `align → advance → supplement → ledger-capture → ledger-judge → outline → dashed`。
5. 单项失败不会阻断后续；新楼、切聊天、关插件、时旅会使剩余项过期。
6. 刷新坐标、楼内点/轴、线状态、日台、本轮拍与【改】。
7. 时间戳优先直接落日期；无有效戳时才按设置调用机械 API。

重 roll / swipe 通过 `same-floor` 闸、楼层签名和旧结果撤回处理，不能按普通新楼累计节拍。

### 4.3 切聊天

`runtime/chat-changed.js`：

1. 开新边界 epoch；
2. 同步清线、面、刻度、律四路聊天注入；
3. 中止或重置所有在途 controller、队列、对话框、时旅和缓存；
4. 清侧栏瞬态；
5. 加载外置根；
6. 执行旧数据和稳定 ID 迁移；
7. 再次核对 chatId，过期则返回 `superseded`；
8. 新聊天仍有效且插件开启时恢复节拍、面板和注入。

写入 owner guard 保护“旧任务写进新聊天”；注入先清后恢复保护“旧提示词进入新聊天生成”。

## 5. 数据所有权

### 5.1 跟聊天走

`chat_metadata`：

- `sp-store`：点、线、面、间对话、冷知识、轴数据、日期锚、本轮拍、活动、节拍、笺、律、灯状态；
- `sp-memory`：内置记忆；
- `sp-theater`：棱永久稿；
- `sp-ledger`：刻度；
- `sp-storage`：外置存储定位标记，不是业务根。

`store.js` 的 `OWN_KEYS` 是删除白名单。不得删除柏宝书或其他扩展的 metadata。

### 5.2 全局扩展设置

SillyTavern `extension_settings['schedule-planner']`：

- API 与预设；
- 功能、注入、显示、节拍开关；
- 历法模板与角色绑定；
- 记忆、正文标签、字体等全局偏好。

### 5.3 本设备

`localStorage` 只应用于窗口/FAB 位置尺寸、折叠状态等本机偏好，由 `runtime/device-preferences.js` 读写。棱草稿和 swipe 缓存仍留各自模块（已各自捕获存储异常），不迁进该适配器。它不是聊天数据源，也不是确认写入失败后的备用数据库。

### 5.4 全局文件

坐标通过文件 API 保存，是跨聊天收藏，不跟单串聊天走。

## 6. 日期、日程和剧情账规则

### 日期优先级

1. 正文 SDC 时间戳；
2. 无有效戳时按节拍调用日期兜底；
3. 用户在轴上手调；
4. 完整公历年月日可推星期；仅月日不得用假年推星期。

日期锚是聊天本地数据。只有日历日改变才滚点和触发日期制线推进；同日改钟点不滚动。

### 点

- 目标窗口为今天 + 后两天，共三天；
- 每天至少一个完整 Event；
- 空天仍占槽，避免日期错位；
- Future 必须带具体月日；
- 完成是删除，不另建完成栏；
- 锁定项默认不由模型修改；
- 生成与对齐的语义不同，失败重试必须保留原 kind。

### 线

- 推进模式：按换日、按楼、仅手动；
- 阶段：起线、延展、成形、收束、淡出；
- 收束/淡出是终态，不再注入；
- 未锁活线进入终态时，同次生成按规则补新线；
- 当前上限与提示词/校验器共同约束，不能在 UI 层静默截断。

### 面

- 是节点序列 + 1-based 语义游标（0 表示无当前节点）；
- 自动判定只移动游标；
- 刷新分当前节点、续写、全部替换；
- 当前节点没有稳定 ID，因此撤回仍以整份快照为主。

### 轴与时旅

- 轴保存历法描述、全年节日和追加纪念日；
- 补录按 AI 楼间隔，不随每次换日；
- 时旅落地楼抑制普通自动化，改走目标日专用步骤；
- 有故事年时执行真实跨年；没年时保持年环语义。

## 7. 提示词与上下文

必须保持“一职一份”：

- `align`：按正文对齐未锁点/线；
- `fight`：只改待改篮点名条目；
- `regen`：重做勾选模块；
- `retry`：复用原 kind 和原意图；
- `hand`：本地手改，不请求 API。

构画自己的生成上下文可包含角色、人设、激活且勾选的世界书、记忆、历法、近景楼和最新正文。最新正文有配置的正文包裹时只取包裹内全文，不再按旧字数截断。

主楼潜伏注入由总闸 + 分项闸共同决定：

- 时间戳合同独立；
- 线、面、刻度默认多为关闭；
- 律必须当前聊天勾选且总闸开启；
- 笺、日台、对账灯、本轮拍永不注入。

## 8. UI 与宿主约束

- 主窗口在 Shadow DOM；楼内框和 toast 在 light DOM，因此 `style.css` 同时加载两处。
- 不使用 `<Teleport to="body">` 之类会跨出 Shadow DOM 的实现。
- 面板、对话框、悬浮球要避开 SillyTavern/TT 键盘、安全区和层级。
- 虚拟化关闭：楼内框走近窗 + observer。
- 虚拟化开启：必须走 ChatSurface `prepareContent`/claim 和同步 disposer，不伪造渲染事件。
- 自动任务保持串行，尤其照顾 TT iOS WebView。
- UI 主题优先继承 SillyTavern 色值，缺失时使用 day/night fallback。

## 10. 已确认决策

1. 通用机制优先，但不合并真实不同的领域语义。
2. 失败与 unknown commit 必须显式，不静默降级。
3. 间不写账，灯写账。
4. 刷新账本手动、串行、不进每楼自动队列。
5. 最新正文、记忆和已选世界书不恢复统一硬截断。
6. 不重复柏宝书的数据领域。
7. 不全量 Vue/React 重写。
8. `index.js` 保持装配根；只迁移有独立语义和测试边界的行为。
9. 稳定 ID 用于本地身份，不进入模型生成合同。
10. Node 契约测试不是宿主/TT 真机验收的替代品。
11. 不把原作者 3.7.11 整仓合进 3.15.0。间卡片只移植分类和展示合同，不恢复一键写账。剧情倾向是作者预设，不进线条目、不进模型可改字段。时间戳历法上下文与点/线生成历法块分开。交互修复并入设备偏好和 UI 优化，不当独立功能。详见 `docs/原作者3.7.9对照.md`。

## 11. 当前开放风险

- TT 虚拟化与真实 iOS 未验收（契约已补，真机仍缺）；
- 外置存储在不同宿主能力组合下仍需运行时矩阵；
- CSS 与装配根体积较大，审查成本高，但不能用大重写解决。
